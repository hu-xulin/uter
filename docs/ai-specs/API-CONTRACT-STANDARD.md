# API-CONTRACT-STANDARD
# Uter API 接口契约规范

**项目：** Uter  
**文档类型：** API 与接口契约标准  
**适用范围：** 前端 API、后端 API、内部服务接口及第三方集成  
**规范级别：** 强制执行

---

## 1. 规范目标

确保 API 的请求、响应、错误、数据类型和行为具有一致性。

前端和后端必须遵循同一份接口契约，不得分别猜测或维护不一致的数据结构。

## 2. API 设计原则

- 接口职责清晰。
- 命名统一。
- 输入明确。
- 输出稳定。
- 错误可识别。
- 权限明确。
- 兼容性可控。
- 行为可测试。
- 文档与实现同步。

## 3. 接口命名

API 路径必须遵循项目既有命名风格。

不得在同一资源中随意混用不同命名习惯。

HTTP Method 应符合操作语义：

- GET：读取。
- POST：创建或执行操作。
- PUT：整体替换。
- PATCH：部分更新。
- DELETE：删除或执行删除语义。

不得为了方便使用不符合语义的方法。

## 4. Request 契约

每个接口必须明确：

- 请求方法。
- 路径。
- Header。
- Query 参数。
- Path 参数。
- Body。
- 字段类型。
- 是否必填。
- 默认值。
- 格式要求。
- 校验规则。
- 权限要求。

外部输入必须进行服务端校验。

不能仅依赖前端校验保证数据安全。

## 5. Response 契约

每个接口必须定义：

- 成功响应。
- 失败响应。
- 字段类型。
- 可空规则。
- 时间格式。
- 金额单位。
- 分页结构。
- 数据兼容规则。

禁止同一字段在不同接口中使用不一致的含义。

## 6. 数据格式

必须明确以下内容：

### 时间

- 明确使用的时间格式。
- 明确时区。
- 明确时间戳单位。
- 避免前后端对 UTC 和本地时间产生误解。

### 金额

- 明确币种。
- 明确单位。
- 明确精度。
- 避免使用不安全的浮点数进行金额运算。

### Token

- 明确 Token 数量的类型。
- 明确输入、输出和缓存 Token 的区分。
- 明确计费精度和舍入规则。

### 空值

明确区分：

- 字段不存在。
- null。
- 空字符串。
- 空数组。
- 数值 0。

不得让前端通过猜测判断字段含义。

## 7. 统一错误处理

错误响应必须具有稳定结构。

建议逻辑结构：

- code：机器可识别的错误码。
- message：面向调用方的错误说明。
- request_id：请求追踪标识。
- details：允许公开的附加信息。

实际字段必须以 Uter 现有 API 契约为准，不得擅自引入第二套错误体系。

错误码必须稳定，不能只依赖错误文本进行业务判断。

## 8. 身份认证与权限

必须明确：

- 是否需要认证。
- 使用何种认证机制。
- 权限要求。
- 资源归属校验。
- 管理员权限。
- API Key 权限。
- 限流策略。

必须在服务端执行权限检查。

隐藏前端按钮不等于完成权限控制。

## 9. 幂等性

涉及以下操作时必须评估幂等性：

- 支付。
- 充值。
- 余额调整。
- 订单创建。
- Token 结算。
- 退款。
- 外部 Webhook。
- 任务触发。

必须明确幂等键的生成、作用范围、保存期限和重复请求行为。

## 10. API 兼容性

修改公共 API 前必须评估：

- 已有前端调用。
- 外部 API 使用者。
- 第三方集成。
- 移动端版本。
- 历史数据。
- API SDK。

破坏性变更必须制定版本、迁移或兼容方案。

不得无提示地删除已有字段或改变字段含义。

## 11. API Schema

建议使用项目已有的 OpenAPI 或等价契约工具。

要求：

- 契约有唯一事实来源。
- 前后端类型尽量自动生成。
- 契约变更纳入代码审查。
- 检查不兼容修改。
- 自动校验实现与契约一致性。

不得为了形式化而重复维护多份互相独立的接口定义。

## 12. 第三方 API

必须评估：

- 认证方式。
- 请求签名。
- 超时。
- 重试。
- 限流。
- 错误转换。
- 版本变化。
- 数据校验。
- 敏感信息脱敏。

第三方响应不得未经校验直接进入核心业务状态。

## 13. 测试要求

API 测试至少覆盖：

- 正常请求。
- 参数错误。
- 未认证。
- 权限不足。
- 资源不存在。
- 重复请求。
- 异常响应。
- 超时。
- 兼容性。

核心接口必须覆盖关键业务边界。

## 14. 完成定义

API 只有在契约、实现、权限、错误处理、测试和文档保持一致时，才可标记为完成。

---

**API 契约是前后端和服务之间的共同事实来源。**
