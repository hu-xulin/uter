# SECURITY-STANDARD
# Uter 安全开发规范

**项目：** Uter  
**文档类型：** 信息安全与安全开发标准  
**适用范围：** 所有代码、接口、数据、配置和外部集成  
**规范级别：** 强制执行

---

## 1. 规范目标

保证 Uter 在身份认证、权限管理、数据处理、支付、API Relay 和第三方集成中的安全性。

安全要求不得因开发便利而被绕过。

## 2. 安全基本原则

- 默认拒绝。
- 最小权限。
- 深度防御。
- 输入不可信。
- 输出受控。
- 敏感信息最小化。
- 安全失败关闭。
- 操作可审计。
- 依赖可追溯。

## 3. 身份认证

必须正确处理：

- 登录认证。
- Session / Token。
- 令牌过期。
- 令牌撤销。
- 密码或验证码验证。
- 多设备会话。
- 异常登录。
- 账户状态。

不得自行绕过已有认证中间件。

## 4. 权限控制

所有敏感操作必须在服务端验证权限。

包括：

- 用户数据访问。
- API Key 管理。
- 余额查询与调整。
- 充值订单。
- 退款。
- 模型管理。
- 渠道管理。
- 系统设置。
- 管理员操作。

必须防止越权访问和 IDOR。

## 5. 输入验证

所有外部输入都必须视为不可信。

重点检查：

- SQL 注入。
- 命令注入。
- XSS。
- SSRF。
- 路径穿越。
- 文件上传。
- 不安全反序列化。
- 参数污染。
- 请求体大小。
- 资源消耗攻击。

必须进行服务端验证。

## 6. API 安全

必须考虑：

- HTTPS。
- 认证。
- 授权。
- 限流。
- 请求大小限制。
- 超时。
- CORS。
- CSRF（适用时）。
- 重放攻击。
- 请求签名。
- 错误信息泄露。

不得仅依赖前端控制安全边界。

## 7. API Key 与密钥管理

必须：

- 使用安全随机数生成密钥。
- 限制密钥权限。
- 支持撤销和轮换。
- 限制密钥可见范围。
- 对日志进行脱敏。
- 使用受控 Secrets 管理。
- 避免将密钥写入代码和提交历史。

不得明文输出完整 API Key 或支付私钥。

## 8. 支付安全

支付相关实现必须：

- 验证签名。
- 验证订单号。
- 验证商户身份。
- 验证支付金额。
- 验证币种。
- 验证订单状态。
- 防止重复通知。
- 防止重放攻击。
- 保护回调入口。
- 保留审计证据。

支付成功不能仅根据浏览器跳转参数判断。

## 9. AI Relay 安全

必须考虑：

- API Key 泄露。
- 上游请求伪造。
- SSRF。
- 上游响应污染。
- 请求超时。
- 恶意超大响应。
- 流式连接耗尽。
- 越权模型访问。
- 价格和用量篡改。
- 计费数据伪造。

必须校验模型、渠道和用户权限之间的关系。

## 10. 数据保护

敏感数据必须：

- 限制访问。
- 必要时加密。
- 按最小范围展示。
- 避免进入普通日志。
- 避免进入调试输出。
- 按业务和合规要求保留或删除。

## 11. 文件上传

必须检查：

- 文件大小。
- 文件类型。
- 文件内容。
- 文件名。
- 存储路径。
- 访问权限。
- 恶意文件风险。

不得只根据扩展名判断文件安全。

## 12. 依赖安全

新增或更新依赖时必须检查：

- 已知漏洞。
- 来源可信度。
- License。
- 维护状态。
- 供应链风险。
- 锁文件变化。

不得随意执行不可信安装脚本。

## 13. 安全日志和审计

敏感操作应记录：

- 操作主体。
- 操作时间。
- 操作对象。
- 操作类型。
- 结果。
- 关联请求或任务标识。

不得在审计日志中保存完整秘密。

## 14. 安全禁止事项

AI 严禁为了通过测试或快速实现功能而：

- 关闭权限验证。
- 关闭支付验签。
- 关闭 TLS 验证。
- 允许任意跨域。
- 硬编码真实密钥。
- 使用固定弱密码。
- 放宽所有输入限制。
- 暴露内部错误堆栈。
- 禁用安全扫描。
- 删除安全测试。

确需改变安全策略时，必须先说明理由、风险和替代措施，并获得相应授权。

## 15. 安全测试

按适用情况执行：

- 静态安全扫描。
- 依赖漏洞扫描。
- Secret Scan。
- 权限测试。
- 输入验证测试。
- Webhook 验签测试。
- 越权测试。
- SSRF 测试。
- 并发与重放测试。

## 16. 漏洞处理

发现漏洞后：

1. 记录证据。
2. 判断严重程度。
3. 确认影响范围。
4. 制定缓解方案。
5. 在授权范围内修复。
6. 添加安全回归测试。
7. 复核相关调用路径。

重大安全问题必须优先处理。

## 17. 完成定义

必须满足：

- 认证和授权完整。
- 输入校验有效。
- 敏感数据受保护。
- 密钥管理合理。
- 外部集成经过验证。
- 安全测试已执行。
- 未解决风险已披露。

---

**任何 AI 不得以功能实现为理由降低 Uter 的安全等级。**
