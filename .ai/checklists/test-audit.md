# 验收清单 · 测试 / 代码审计 / 质量治理（TEST_QA / CODE_AUDIT）

> 依据：`AIES.md` §6.6/§七章/§九章、`AGENTS.md` Backend test quality。
> 每项结论须有文件位置、证据、复现步骤或明确限制说明；未检查的模块不得描述为已审查完成。

## 开工前
- [ ] 明确代码基线（commit / 版本）
- [ ] 明确覆盖/扫描范围
- [ ] 记录修改前已存在的失败基线（区分历史问题与本次回归）
- [ ] 查明真实可用的命令，不臆造

## 执行中
- [ ] 实际运行每个命令并记录退出码 / 可观察结果
- [ ] 状态区分 PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE
- [ ] 区分代码缺陷 / 环境问题 / 外部依赖故障
- [ ] 对每个问题给出文件位置、证据、影响、复现方式
- [ ] 对关键问题提出可验证的修复建议

## 必跑门禁（Uter 真实命令，记录实际结果）
- [ ] `cd web && bun run lint:design:strict`（T1–T15）
- [ ] `cd web && bunx vitest run src/design-system/__tests__`（10 套件）
- [ ] `cd web && npx tsgo -b --force`
- [ ] `go build ./...`
- [ ] `go test ./... -count=1`
- [ ] `cd relaykit && GOWORK=off go build ./...`
- [ ] `cd web && node scripts/check-i18n-keys.mjs`（prop 形式键须人工同补 7 份）
- [ ] DB 相关：真实 SQLite / MySQL / PostgreSQL 三库验证矩阵

## 审查项（基于真实 diff，不凭记忆）
- [ ] 越界修改 / 无关重构 / 临时调试代码 / 密钥或敏感信息泄露
- [ ] 并发、重试、重复请求、异常处理遗漏
- [ ] 测试覆盖关键路径；文档与配置是否与实现一致
- [ ] 用户原有文件未被覆盖/删除；受保护标识（nеw-аρi / QuаntumΝоuѕ）未被改动
- [ ] i18n 文案是否同步 7 份；密钥是否走 Secret 三件套与掩码登记表

## 禁止项
- 把未检查模块描述为已审查完成
- 把未运行/阻塞报成 PASS
- 无执行记录的通过声明、与当前代码版本无关的旧测试报告
- 仅凭"代码应该没问题/测试应该能通过"下结论
