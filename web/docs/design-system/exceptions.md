# Exceptions

规范的价值取决于「例外是否被记录」。凡是无法接入 Token 的场景，都必须在这里
登记：理由、影响范围、退出条件。

代码侧的对应登记在 `scripts/check-design-tokens.mjs` 的 `ALLOWLIST`。
两处必须同步 —— 只改一处说明例外已经失控。

## 已登记例外

### E1 · 输入控件保持 16px

- **位置**：`components/ui/input.tsx`、`textarea.tsx`、`select.tsx` 触发器；
  `styles/index.css` 的移动端强制规则。
- **与文档差异**：文档 Input 用 `body-sm`（14/20），实际用 16/24。
- **理由**：iOS Safari 在 `font-size < 16px` 的控件获得焦点时会自动放大页面。
  14px 输入框在手机上每点一次就跳一次缩放，体验不可接受。
- **退出条件**：仅当目标浏览器不再有该行为，或改为原生应用时。

### E2 · 密集等宽文本用 14/22

- **位置**：表格单元格、日志列、定价卡片、详情页内嵌代码块中的 API Key /
  模型 ID / 请求 ID / 计费表达式。
- **与文档差异**：文档 `mono` 为 16/24，此处用 14/22
  （`leading-[var(--ds-line-mono-dense)]`）。
- **理由**：这些标识符出现在列宽受限的表格里。16px 等宽会让请求日志表的行高
  增加 20% 以上、列宽溢出，一屏能看到的行数显著减少。
- **退出条件**：表格改为卡片式布局，或列宽不再受限时。

### E3 · 行内代码用 14/20

- **位置**：Markdown 渲染的行内 `<code>`。
- **与文档差异**：文档 `mono` 为 16/24，此处与上下文正文（14px）对齐。
- **理由**：行内代码嵌在 14px 正文里，若单独用 16px 会造成行内字号跳变和行高
  抖动，可读性反而下降。
- **退出条件**：正文基准改为 16px 后，行内代码同步为 16px。

### E4 · 图表 canvas 字号为数值

- **位置**：`features/*/lib/charts.ts`、`features/*/lib/flow.ts`、VChart option 里的
  `fontSize`。
- **理由**：VChart 走 canvas 绘制，不读 CSS 变量，`fontSize` 必须是数字。
- **约束**：取值必须等于「图表轴标签 12px」，不得随意写 10 或 11。
- **退出条件**：无（canvas 渲染的固有限制）。

### E5 · 第三方客服挂件

- **位置**：`features/customer-service/CustomerServiceWidget.tsx`。
- **理由**：挂件样式由其自身注入，无法接入本项目 Token。
- **退出条件**：换成自研组件或挂件提供主题变量注入。

### E6 · 错误页巨型状态码

- **位置**：`features/errors/*.tsx` 的 `text-[7rem]`。
- **理由**：401/403/404/503 的数字是装饰性图形，不属于内容层级，不参与九档阶梯。
- **退出条件**：无。

## 待办（尚未完成，不是例外）

以下三项是**已知未完成**，不要当成已批准的例外：

### D1 · 控件高度未整体抬升

文档要求按钮 36px、输入框 40px；当前按钮 32px、输入框 32px。

未执行的原因：输入框与按钮在搜索栏、工具栏、筛选行里大量成对出现，两者当前
共用 32px 基线。整体抬升需要逐页做视觉回归，否则会出现 36 与 40 并排错位。

Token 已就位（`--ds-control-height-md` / `--ds-button-height-md`），后续可以一处
切换、逐页验证。

### D2 · 投影尚未全站清理

文档要求「除弹窗与浮层外一律不投影」；历史代码里仍散落 `shadow-xs` / `shadow-sm`
（卡片、面板、表格容器）。

未执行的原因：涉及面广且纯视觉，需要配合视觉回归基线一起做，避免一次性改动
过多无法定位问题。

### D3 · 业务组件尚未改写

Dashboard、API Key、模型管理、日志、账单等高频页面的业务组件，目前仍直接使用
`text-*` 工具类而不是 `Text` / `Heading`。

已完成的是「消除违规字号」这一层；「业务组件组合基础组件」是下一阶段的工作，
需要逐页迁移并回归。

## 新增例外的流程

1. 先确认现有 Token 真的覆盖不了 —— 绝大多数「需要新字号」其实是排版没用对；
2. 在本文档追加一节，写清位置、差异、理由、影响范围、退出条件；
3. 在 `scripts/check-design-tokens.mjs` 的 `ALLOWLIST` 加对应条目并写明理由；
4. 提交说明里引用例外编号。

没有退出条件的例外不接受。
