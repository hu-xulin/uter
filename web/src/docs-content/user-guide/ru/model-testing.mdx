# Тестирование моделей

Перед подключением модели к Uter проверьте по шагам: соединение, работоспособность, стабильность и корректность списаний. Так проблемы находятся до продакшена.

Сначала пройдите сценарий в **Песочнице** консоли, затем повторите через API: это быстро разделяет «модель недоступна» и «запрос составлен неверно».

## Что нужно заранее

| Пункт | Описание | Где взять |
| --- | --- | --- |
| **Базовый URL** | Выделенная точка входа для API `https://api.uter.ai/v1`; также подходит адрес используемой консоли + `/v1`. Другие домены не являются официальными точками входа | Главная страница справки по API; или адрес сайта консоли + `/v1` |
| **Ключ API** | Например, `sk-xxxxxxxx`. Это секрет, равный паролю: не публикуйте, не встраивайте во фронтенд, не коммитьте | Общие → Ключи API → Создать ключ API |
| **Квота** | Внутренняя единица биллинга: **по умолчанию 500 000 квоты = 1 USD**, это соотношение меняется в Настройки системы → Биллинг; каждая модель использует свои правила расчёта, кошелёк и журналы показывают настроенную валюту сайта. При исчерпании запросы отклоняются | Личное → Кошелёк; Общие → Журнал использования |
| **Имя модели** | Зарегистрированное в Uter имя (может отличаться от исходного) | Публичная страница цен `/pricing`; или `id` из `GET /v1/models` |

### Канал и группа — разные измерения

- **Группа**: определяет коэффициент биллинга и доступный набор моделей. Ключ тарифицируется и маршрутизируется по своей группе.
- **Канал**: вышестоящий провайдер, который реально обслуживает модель (канал Uter, агрегирующий, общий и т. п.). Модель может обслуживаться несколькими включёнными каналами или одним.

Поэтому доступность и цена одной модели зависят от группы и времени. «Нет доступного канала» означает, что для вашей группы нет включённого канала с этой моделью, а не ошибку формата запроса.

<Callout type="warn">
  Ключ — это пароль: только на сервере или в менеджере секретов. Никогда в браузер, никогда в открытые журналы, никогда в Git.
</Callout>

### Проверьте состояние и ограничения ключа

Состояния: **включён, отключён, истёк, квота исчерпана**. При создании/редактировании доступны:

- **Группа**: определяет коэффициент биллинга и доступные модели; можно также задать «автоматический порядок групп» и повторы между группами.
- **Срок действия**: по умолчанию «не истекает»; после истечения — 401.
- **Лимит квоты**: вводится в настроенной валюте сайта (по умолчанию USD) или «без ограничений». После исчерпания — «исчерпана».
- **Ограничения моделей**: разрешить только выбранные. Если не выбрано ни одной, ключ не может вызвать ничего.
- **Список IP**: поддержка CIDR (например, `203.0.113.0/24`); прочие источники отклоняются.
- **Разрешить запрос квоты пользователя**: доступ к `/v1/dashboard/billing/*`.
- **Количество**: можно создать несколько ключей сразу; для теста достаточно оставить один.

<Callout type="info">
  Для тестового ключа разрешите только проверяемую модель и отключите повторы между группами: иначе запросы могут уйти на неожиданные каналы и исказить выводы о соединении и биллинге.
</Callout>

## Быстрая проверка: Песочница

Чат → Песочница использует тот же путь вызова, что и API.

1. Откройте выбор модели: слева во всплывающей панели выберите **канал**, справа — одну из его моделей. По умолчанию выбран первый канал в списке.
2. Отправьте сообщение и наблюдайте ответ (по умолчанию потоковый).
3. В параметрах включите нужное: `temperature`, `top_p`, `max_tokens`, `frequency_penalty`, `presence_penalty`, `seed`. **Отправляются только включённые параметры** (`max_tokens` и `seed` по умолчанию выключены).
4. Можно остановить генерацию, перегенерировать, редактировать или скопировать сообщение, посмотреть исходный ответ, удалить сообщение или очистить диалог (с подтверждением).
5. Кнопки **вложений и веб-поиска в поле ввода — это заглушки в разработке**: нажатие только показывает сообщение о неподдержке. Для зрения используйте `image_url` через API (шаг 6), для веб-поиска — `POST /v1/tools/search`.

Песочница списывает квоту по тем же правилам — удобно для итераций; финальную проверку делайте через API.

## Проверьте модель и цену

Публичная страница цен `/pricing` позволяет:

- искать модель;
- фильтровать по **каналу, вендору, тегу модели, типу ценообразования и типу эндпоинта** (пять фильтров). Типы ценообразования: за токены, за запрос, за задачу и динамическое; типы эндпоинтов: Chat / Response / Anthropic / Gemini / Rerank / Image / Embeddings / Video;
- смотреть режим биллинга, контекст и поддерживаемые эндпоинты, переключать **стандартную цену / цену пополнения**, единицы **за 1M / за 1K токенов**, семь видов сортировки и вид карточек / таблицы;
- сравнивать **цену Uter** с **официальной ценой**, скидку / наценку. Модели с посекундным биллингом (некоторые видео- и аудиомодели) показывают ставку `/ second` и официальную справочную цену;
- обратите внимание: боковая панель каналов по умолчанию выбирает **Claude-Basic** и показывает только его модели; нажмите «Все каналы» или откройте `?channel=all`, чтобы увидеть все.

<Callout type="warn">
  Если на карточке указано «цена не настроена», показан исходный текст формулы биллинга или отсутствует официальная цена — это проблема данных о ценах на стороне платформы, а не ошибка запроса. Запишите модель и канал и обратитесь в платформу; не разбирайте выражение самостоятельно.
</Callout>

## Измерения тестирования

Одиннадцать пунктов: первые четыре — «можно ли использовать», следующие пять — «стабильно ли и корректно ли списывается», последние два — асинхронные задачи и наблюдаемость.

1. **Связность и авторизация** — URL, ключ, список IP.
2. **Список и доступность моделей** — модель существует и есть обслуживающий канал в группе.
3. **Базовый диалог** — минимальный запрос даёт ответ.
4. **Параметры и расширенные возможности** — стриминг, `temperature`, `max_tokens`, tools/function calling, зрение, JSON-режим, системный промпт.
5. **Стриминг (SSE)** — поточный вывод и корректный разбор.
6. **Производительность** — TTFT, общая задержка, длинный контекст.
7. **Стабильность и лимиты** — параллелизм, повторы, 429, насыщение апстрима.
8. **Квота и биллинг** — списания совпадают с журналами.
9. **Ошибки и границы** — понятные и машинно-обрабатываемые ошибки.
10. **Асинхронные модели** — отправка, опрос и скачивание (изображения / видео / музыка).
11. **Наблюдаемость** — журналы показывают модель, канал, задержку, квоту и причину отказа.

## Пошагово (API)

- `BASE=https://ваш-домен/v1` (замените)
- `TOKEN=sk-your-token-here` (полный ключ из консоли)

Примеры на `curl`. При локальном прокси добавьте `--noproxy '*'`.

### Шаг 1 · Связность + авторизация

```bash
BASE=https://ваш-домен/v1
TOKEN=sk-your-token-here

curl --noproxy '*' -s "$BASE/models" \
  -H "Authorization: Bearer $TOKEN" | head -c 800
echo
```

Ожидается JSON с `object: "list"` и несколькими `id` → связность и авторизация в порядке. 401 «Недействительный токен» — неверный или отключённый ключ; «нет доступа ни к каким моделям» — ограничения моделей не пропускают цель.

<Callout type="info">
  Поддерживается и нативная авторизация: Claude — `POST /v1/messages` с `x-api-key` и `anthropic-version: 2023-06-01`; Gemini — `GET /v1beta/models` с `x-goog-api-key` (или `?key=`). Совместимые с OpenAI эндпоинты используют `Authorization: Bearer`.
</Callout>

### Шаг 2 · Список и карточка модели

```bash
curl --noproxy '*' -s "$BASE/models" \
  -H "Authorization: Bearer $TOKEN" \
  | python3 -m json.tool | grep '"id"' | head -40

curl --noproxy '*' -s "$BASE/models/ваша-модель" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```

<Callout type="warn">
  Нет модели? Сначала проверьте страницу цен `/pricing` по каналам, затем обратитесь в платформу. Боковая панель каналов по умолчанию показывает только Claude-Basic — нажмите «Все каналы» или выберите конкретный канал. Не угадывайте имена: будет 404 или «нет доступного канала».
</Callout>

### Шаг 3 · Минимальный диалог (без стриминга)

```bash
curl --noproxy '*' -s "$BASE/chat/completions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ваша-модель",
    "messages": [{"role": "user", "content": "Представься одним предложением."}],
    "max_tokens": 200
  }' | python3 -m json.tool
```

Успех: `choices[0].message.content` содержит текст, `usage` — `prompt_tokens` / `completion_tokens`.

### Шаг 4 · Стриминг (SSE)

```bash
curl --noproxy '*' -N -s "$BASE/chat/completions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ваша-модель",
    "messages": [{"role": "user", "content": "Посчитай до 10."}],
    "stream": true
  }'
```

Успех: блоки `data: {...}` приходят по мере генерации и завершаются `data: [DONE]`. Для curl обязателен `-N`; в SDK включите `stream: true` и отключите общую буферизацию.

### Шаг 5 · Function calling

```bash
curl --noproxy '*' -s "$BASE/chat/completions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ваша-модель",
    "messages": [{"role": "user", "content": "Какая сейчас погода в Пекине?"}],
    "tools": [{
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "Погода в городе",
        "parameters": {
          "type": "object",
          "properties": {"city": {"type": "string"}},
          "required": ["city"]
        }
      }
    }]
  }' | python3 -m json.tool
```

Успех: в ответе есть `choices[0].message.tool_calls`. Проверяйте каждую расширенную возможность отдельно.

### Шаг 6 · Зрение (только для моделей с изображениями)

```bash
curl --noproxy '*' -s "$BASE/chat/completions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ваша-модель-со-зрением",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "Что на изображении?"},
        {"type": "image_url", "image_url": {"url": "https://example.com/demo.png"}}
      ]
    }]
  }' | python3 -m json.tool
```

Изображение должно быть публично доступным; локальные файлы платформа не читает.

### Шаг 7 · Базовая задержка

```bash
for i in 1 2 3; do
  curl --noproxy '*' -s -o /dev/null -w "попытка $i ttfb=%{time_starttransfer}s total=%{time_total}s HTTP=%{http_code}\n" \
    "$BASE/chat/completions" \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"model":"ваша-модель","messages":[{"role":"user","content":"привет"}],"max_tokens":128}'
done
```

Сравните TTFT и общее время с SLA. Дополнительно проверьте длинный промпт (8k / 32k токенов).

### Шаг 8 · Квота и биллинг

`/v1/dashboard/billing/usage` возвращает **накопленный расход** (`total_usage`), а не остаток — остаток смотрите в Личное → Кошелёк. `total_usage` пересчитывается в валюту отображения сайта и выражается в **1/100 этой валюты** (центы USD на сайте в USD), поэтому разницу до/после вызова нужно разделить на 100, чтобы получить доллары. Сравнивайте до/после вызова:

```bash
# До вызова
curl --noproxy '*' -s "$BASE/dashboard/billing/usage" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool

# (здесь выполните шаг 3)

# После вызова
curl --noproxy '*' -s "$BASE/dashboard/billing/usage" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```

Сверяйте с `usage` ответа и детализацией в Общие → Журнал использования / Журнал задач.

`GET /v1/dashboard/billing/subscription` — это совместимый с OpenAI запрос **предела квоты**. Его поля называются `*_usd`, но значения следуют валюте отображения сайта (USD / CNY / tokens) и не отражают реальную платёжную подписку; `access_until` заполняется только в режиме статистики по токенам.

### Шаг 9 · Читаемость ошибок

```bash
curl --noproxy '*' -s -w "\nHTTP=%{http_code}\n" "$BASE/chat/completions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model":"ваша-модель","messages":[{"role":"user","content":"hi"}],"max_tokens":999999}'
```

Ожидается конверт `{"error":{"message":...,"type":...,"code":...}}` и статус 4xx, а не пустое тело или трассировка 500.

## Асинхронные модели (изображения / видео / музыка)

Схема **отправка → опрос → скачивание**:

1. **Отправка** через включённый плагин в разделе Администратор → Плагины каналов (`/task-plugins`, только суперадминистраторы): общий `POST /v1/tasks/<ключ-плагина>`, видео `POST /v1/video/generations` или в стиле OpenAI `POST /v1/videos`. Совместимый `POST /v1/images/generations` обслуживается соответствующим каналом / плагином.
2. **Опрос** по `task_id`: `GET /v1/tasks/<task_id>`, `GET /v1/video/generations/<task_id>` или `GET /v1/videos/<task_id>`. До завершения — в очереди / в обработке.
3. **Артефакты**: `GET /v1/tasks/<task_id>/artifacts` — список, `GET /v1/tasks/<task_id>/artifacts/<artifact_key>/content` — скачивание (также работает параметр подписанного доступа без токена). Для видео — `GET /v1/videos/<task_id>/content`.
4. **Проверка**: в Общие → Журнал задач смотрите статус, прогресс, длительность и причину сбоя. **Возвраты не попадают в журнал задач** — они появляются как записи типа «Возврат за асинхронную задачу» в Общие → Журнал использования.
5. **Границы**: вызовите таймаут или неверный параметр и убедитесь, что задача переходит в сбой, а не зависает.

## Диагностика

| # | Симптом | HTTP | Вероятная причина | Решение |
| --- | --- | --- | --- | --- |
| **A1** | Недействительный токен | 401 | Ключ обрезан, с опечаткой или отключён | Скопируйте полный ключ в Общие → Ключи API, статус «включён» |
| **A2** | Срок действия токена истёк | 401 | Истёк срок | Создайте новый ключ или установите «не истекает» |
| **A3** | Квота ключа исчерпана | 401 | Исчерпана квота ключа | Пополните квоту ключа в Общие → Ключи API или создайте новый |
| **A4** | Your IP address is not on this token's allowlist | 403 | IP вне списка (CIDR) | Добавьте IP/диапазон или отключите ограничение в тестовой среде |
| **A5** | Нет доступа ни к каким моделям | 403 | Ограничения моделей пусты | Отредактируйте ключ и выберите модели |
| **A6** | Нет доступа к модели «xxx» | 403 | Модель вне ограничений | Обновите ограничения или смените ключ |
| **A7** | Нет соединения / таймаут | — | Неверный URL, сертификат, закрытая сеть | Проверьте выделенную точку входа `https://api.uter.ai/v1` или адрес вашей консоли + `/v1`; при прокси `--noproxy '*'` |
| **B1** | Недостаточно квоты | 403 | Квота аккаунта/ключа исчерпана | Пополните Личное → Кошелёк или ключ в Общие → Ключи API; проверьте шагом 8 |
| **B2** | Нет доступного канала для модели «xxx» в группе «default» | 503 (иногда 400) | Нет включённого канала | Проверьте `/pricing` по каналам (боковая панель по умолчанию выбирает Claude-Basic — нажмите «Все каналы»); обратитесь в платформу, не угадывайте имена |
| **B3** | 404 / модель не найдена | 404 | Неверное имя или нет доступа | Получите `id` шагом 2 |
| **C1** | Достигнут лимит запросов | 429 | Лимит ключа/платформы | Снизьте параллелизм, экспоненциальный backoff, проверьте RPM/TPM |
| **C2** | Группа/апстрим насыщены | 429 / 503 | Временная нехватка ёмкости | Повторите позже с backoff; при необходимости обратитесь в платформу |
| **C3** | Редкие 5xx / таймауты, успех после повтора | 5xx | Нестабильность апстрима | Повтор с backoff; платформа тоже повторяет ограниченно |
| **D1** | Стриминг приходит сразу целиком | — | Буферизация клиента | `-N` в curl; `stream: true` и без общей буферизации в SDK |
| **D2** | Кракозябры | — | Кодировка/разбор | UTF-8 с обеих сторон; если `json.tool` корректен — проблема в терминале |
| **D3** | Вывод обрезан | — | Мало `max_tokens` или лимит модели | Увеличьте `max_tokens`, используйте стриминг |
| **E1** | Списание не совпадает с ожиданием | — | Скрытые токены (рассуждения, кэш, инструменты) или разные коэффициенты | Сверяйте `usage` и детализацию в Общие → Журнал использования |
| **E2** | Function calling / JSON-режим не работают | — | Модель не поддерживает | Проверьте шагом 5; предусмотрите деградацию |
| **E3** | На карточке указано «цена не настроена», показан исходный текст формулы или нет официальной цены | — | Проблема данных о ценах / официальной цене на стороне платформы | Запишите модель и канал, обратитесь в платформу; не разбирайте выражение и не меняйте коэффициенты сами |
| **F1** | 400 с «объявлением» | 400 | Уведомление апстрима | Проверьте запрос и обратитесь в платформу с текстом ошибки |

<Callout type="idea">
  Два правила: при «нет канала / модель не найдена» сначала `GET /v1/models` и фильтр по каналам на странице цен `/pricing`, затем платформа. При 401/403 проверьте состояние ключа, ограничения моделей и список IP, затем базовый URL.
</Callout>

## Что делать с 400 (Bad Request)

`400` — сам запрос некорректен (тело или параметры), это не 401 (авторизация), 403 (права/квота) и не 429 (лимит).

| Стиль сообщения | Источник | Действие |
| --- | --- | --- |
| Английский/китайский, «платформенный» | Uter отклонил до передачи | Исправьте запрос |
| Английский, стиль вендора | Апстрим отклонил параметры | Исправьте параметры |
| «Объявление» | Изменение поставки апстрима | Обратитесь в платформу с текстом |

Частые сообщения платформы:

| Сообщение | Смысл | Решение |
| --- | --- | --- |
| `Недействительный запрос: <детали>` | Ошибка валидации тела | Читайте детали после двоеточия |
| `Недействительный запрос, невозможно определить модель.` | Модель не распознана | Проверьте `"model": "..."` |
| `Please specify a model name.` | Нет `model` | Добавьте поле |
| `Недействительный запрос: invalid JSON request body` | Некорректный JSON | Проверьте кавычки, запятые, экранирование |

Сообщения о конфигурации модели или отсутствии цены — на стороне платформы.

Частые ошибки апстрима: `messages is required`, `temperature must be between 0 and 2`, `max_tokens too large`, `Unknown parameter: 'xxx'`, `1 validation error for ...`.

Диагностика за 30 секунд (`curl -i`):

```bash
curl -i https://ваш-домен/v1/chat/completions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model":"<модель>","messages":[{"role":"user","content":"hi"}]}'
```

Сначала читайте `message`.

## Сверка по журналам

Общие → Журнал использования фиксирует время, канал / пользователя (видно администраторам), ключ (с группой), модель, потоковый режим / TPS, входные / выходные токены и токены кэша, квоту, задержку / TTFT и детали (сообщение об ошибке — во всплывающем окне деталей). Общие → Журнал задач фиксирует время отправки, плагин, ID задачи, длительность, статус, прогресс, артефакты и детали (причина сбоя). При интеграции:

- сверяйте модель, группу/канал и квоту с ожидаемыми;
- сохраняйте исходный текст ошибки, чтобы отличать платформу от апстрима;
- не пишите ключи, полные заголовки и персональные данные в свои журналы.

## Чек-лист перед продакшеном

- [ ] **Базовый URL** в конфигурации (env / config service), не в фронтенде.
- [ ] **Ключ** полный, «включён», не истёк, квоты достаточно.
- [ ] **Ограничения моделей** ключа включают нужные модели.
- [ ] При включённом **списке IP** добавлены IP/CIDR продакшена.
- [ ] Подтверждены **группа и доступные каналы** целевой модели (боковая панель страницы цен по умолчанию показывает только Claude-Basic — нажмите «Все каналы» или выберите канал).
- [ ] `GET /v1/models` содержит модель, `id` совпадает с кодом.
- [ ] На странице цен проверены **цена Uter и официальная цена** и правила биллинга; для посекундных / по запросам моделей единицы проверены отдельно. Ни одна карточка не показывает «цена не настроена» или исходный текст формулы.

- [ ] Нужные расширенные возможности (tools / JSON / зрение / длинный контекст) проверены.

- [ ] Реализованы backoff при лимитах и повтор при 5xx апстрима.

### Единый формат ошибок

Эндпоинты, совместимые с OpenAI, по умолчанию используют формат ошибок OpenAI:

```json
{
  "error": {
    "message": "Понятная причина",
    "type": "invalid_request_error | authentication_error | ...",
    "code": "необязательный код",
    "param": "необязательный параметр",
    "metadata": "необязательный дополнительный контекст"
  }
}
```

Есть важные исключения, которые клиент должен обрабатывать отдельно:

| Ситуация | Фактический ответ |
| --- | --- |
| Claude нативный `POST /v1/messages` | Формат Anthropic `{"type":"error","error":{"type":...,"message":...}}` |
| WebSocket (Responses / Realtime) | Ошибки приходят как событийные кадры, а не как HTTP-статус |
| Ошибки биллинговых эндпоинтов | Часто HTTP 200 с `{"error":{"message":...,"type":"uter_error"}}` |
| Ошибки аутентификации / лимитов middleware | `type` может быть `new_api_error`, поле `param` может отсутствовать |
| `GET /v1/models/:model` для неизвестной модели | HTTP 200 с `error.code = "model_not_found"` |

Вместе с HTTP-статусом (401 авторизация / 403 права или квота / 404 нет маршрута / 429 лимит / 501 нереализованный совместимый эндпоинт / 5xx апстрим) этого достаточно для большинства клиентов. **Не полагайтесь только на HTTP-статус**: биллинг и получение модели могут вернуть «HTTP 200 + error», поэтому сначала разбирайте тело ответа.

### Безопасность

- **Ключ = пароль**: только сервер или менеджер секретов.
- **Чистые журналы**: не записывайте заголовок `Authorization`.
- **Лимиты и повторы**: всегда с backoff, иначе шторм повторов превратит лимит в полный отказ.
