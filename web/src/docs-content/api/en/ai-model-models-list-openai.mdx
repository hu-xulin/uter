# Native OpenAI Format

## List models

`GET` `/v1/models`

Returns the models the current token can call. The list is filtered by the token's group, the token's model allowlist and model billing configuration, so different tokens may see different lists.

The response format is selected from the request headers:

- `x-api-key` and `anthropic-version` headers → Anthropic format
- `x-goog-api-key` header or `key` query parameter → Gemini format
- Otherwise → OpenAI format

### Request parameters

| Parameter | In | Type | Required | Description |
|---|---|---|---|---|
| `key` | query | string | No | API key for the Gemini format |
| `x-api-key` | header | string | No | API key for the Anthropic format |
| `anthropic-version` | header | string | No | Anthropic API version |
| `x-goog-api-key` | header | string | No | API key for the Gemini format |

### Response

| Status | Meaning |
|---|---|
| `200` | Model list returned |
| `401` | Authentication failed |

#### `200` fields (OpenAI format)

| Field | Type | Description |
|---|---|---|
| `success` | boolean | Always `true` |
| `object` | string | Always `list` |
| `data` | array&lt;object&gt; | Models |
| `data[].id` | string | Model ID, used verbatim in requests |
| `data[].object` | string | `model` |
| `data[].created` | integer | Registration time (Unix seconds) |
| `data[].owned_by` | string | Owner |
| `data[].supported_endpoint_types` | array&lt;string&gt; | Endpoint families the model serves: `openai`, `anthropic`, `gemini`, `embeddings`, `image-generation`, `openai-video`, `jina-rerank`, `openai-response`, … |

## Retrieve a model

`GET` `/v1/models/{model}`

| Parameter | In | Type | Required | Description |
|---|---|---|---|---|
| `model` | path | string | Yes | Model ID |

Returns the model object (fields as above) when it exists. When it does not, the response is still `200`, with an error body instead:

```json
{"error": {"message": "The model 'xxx' does not exist", "type": "invalid_request_error", "param": "model", "code": "model_not_found"}}
```

Check for an `error` field in the body rather than relying on the HTTP status alone.
