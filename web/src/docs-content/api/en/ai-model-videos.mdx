# Videos

Video generation is asynchronous: submit a task, poll its status, then fetch the result. Uter exposes two entry points:

- **Generic task format**: `/v1/video/generations` returns a `task_id`; provider-specific options go in `metadata`.
- **OpenAI video format**: `/v1/videos` follows the OpenAI Videos API for both request and response, so the official SDK works unchanged.

Request fields differ per provider; read the provider-specific pages below as well.

## Create a video generation task

`POST` `/v1/video/generations`

### Request body (`application/json`)

| Field | Type | Required | Description |
|---|---|---|---|
| `model` | string | Yes | Video model ID from `GET /v1/models`; also selects the channel and pricing |
| `prompt` | string | No | Text prompt |
| `image` | string | No | First-frame image (URL or Base64) |
| `images` | array&lt;string&gt; | No | Multiple reference images (supported by some models) |
| `duration` | number | No | Duration in seconds; the upper bound depends on the model |
| `size` | string | No | Resolution, e.g. `1280x720` |
| `metadata` | object | No | Provider options such as `negative_prompt`, `seed`, `fps` |
| `user` | string | No | Caller-supplied user identifier, for tracing only |

### Response

| Status | Meaning |
|---|---|
| `200` | Task accepted |
| `400` | Invalid request (missing model, duration over the limit, …) |
| `403` | Insufficient quota |
| `429` | Upstream concurrency saturated |
| `503` | Unknown model or no channel available in the current group |

#### `200` fields

| Field | Type | Description |
|---|---|---|
| `id` | string | Task ID (same as `task_id`) |
| `task_id` | string | Task ID |
| `status` | string | Initial status, usually `queued` |
| `model` | string | Model actually used |
| `created_at` | integer | Creation time (Unix seconds) |

Some providers render the response directly from a task plugin; in that case the fields follow the provider page.

## Query a video task

`GET` `/v1/video/generations/{task_id}`

Returns Uter's unified task envelope (`code` is `success` on success):

```json
{
  "code": "success",
  "message": "",
  "data": {
    "task_id": "task_xxx",
    "status": "SUCCESS",
    "progress": "100%",
    "result_url": "https://example.com/result.mp4",
    "fail_reason": "",
    "submit_time": 1699990000,
    "start_time": 1699990010,
    "finish_time": 1699990200,
    "properties": {},
    "data": {}
  }
}
```

| Field | Type | Description |
|---|---|---|
| `code` | string | `success` on success; any other value is an error code |
| `data.task_id` | string | Task ID |
| `data.status` | string | `NOT_START` / `SUBMITTED` / `QUEUED` / `IN_PROGRESS` / `SUCCESS` / `FAILURE` |
| `data.progress` | string | Progress, e.g. `45%` |
| `data.result_url` | string | Result URL once the task succeeds |
| `data.fail_reason` | string | Failure reason |
| `data.properties` | object | Snapshot of the submitted parameters (model, duration, resolution…) |
| `data.data` | object | Raw provider result |

A missing task, or one owned by another user, returns `400` (`task_not_exist`).

## Using the OpenAI video format

`POST` `/v1/videos` accepts `application/json` and `multipart/form-data` with the OpenAI Videos fields: `model`, `prompt`, `seconds`, `size`, `input_reference`, and so on. The response is an OpenAI video object:

```json
{
  "id": "task_xxx",
  "object": "video",
  "model": "sora-2",
  "status": "queued",
  "progress": 0,
  "created_at": 1699990000,
  "seconds": "8",
  "size": "1280x720"
}
```

Companion endpoints:

| Method and path | Description |
|---|---|
| `GET /v1/videos/{id}` | Poll the task; on success returns `completed_at` and the final `status` |
| `GET /v1/videos/{id}/content` | Proxy-download the video file stream |
| `POST /v1/videos/{id}/remix` | Generate again from an existing video (remix) and return a new video object |

`status` values: `queued`, `in_progress`, `completed`, `failed`.
