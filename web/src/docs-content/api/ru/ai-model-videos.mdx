# Видео (Videos)

Генерация видео асинхронна: отправьте задачу, опрашивайте её статус, затем заберите результат. Uter предоставляет две точки входа:

- **Универсальный формат задачи**: `/v1/video/generations` возвращает `task_id`; параметры конкретного провайдера передаются в `metadata`.
- **Формат видео OpenAI**: `/v1/videos` принимает поля OpenAI Videos. Для модели, закреплённой за плагином задачи `openai_video`, и запрос, и ответ следуют OpenAI Videos API, и официальный SDK работает без изменений. Для моделей, не закреплённых за таким плагином, запрос направляется в универсальный ретранслятор задач, и ответ использует конверт задачи (`task_id`, `status: queued`) вместо объекта видео OpenAI.

Набор полей зависит от провайдера — дополнительно смотрите страницу соответствующего формата ниже.

## Создание задачи генерации видео

`POST` `/v1/video/generations`

### Тело запроса (`application/json`)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `model` | string | Да | ID видеомодели из `GET /v1/models`; также определяет канал и тарификацию |
| `prompt` | string | Нет | Текстовый промпт |
| `image` | string | Нет | Изображение первого кадра (URL или Base64) |
| `images` | array&lt;string&gt; | Нет | Несколько референсных изображений (для части моделей) |
| `duration` | number | Нет | Длительность в секундах; верхняя граница зависит от модели |
| `size` | string | Нет | Разрешение, например `1280x720` |
| `metadata` | object | Нет | Параметры провайдера: `negative_prompt`, `seed`, `fps` и др. |
| `user` | string | Нет | Идентификатор пользователя от вызывающей стороны, только для трассировки |

### Ответ

| Статус | Значение |
|---|---|
| `200` | Задача принята |
| `400` | Некорректный запрос (нет model, длительность сверх лимита и т. п.) |
| `403` | Недостаточно квоты |
| `429` | Насыщение параллельных запросов на стороне провайдера |
| `503` | Неизвестная модель или нет доступного канала в текущей группе |

#### Поля `200`

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | ID задачи (совпадает с `task_id`) |
| `task_id` | string | ID задачи |
| `status` | string | Начальный статус, обычно `queued` |
| `model` | string | Фактически использованная модель |
| `created_at` | integer | Время создания (Unix-секунды) |

Некоторые провайдеры формируют ответ напрямую через плагин задачи — тогда поля описаны на странице этого провайдера.

## Запрос статуса задачи

`GET` `/v1/video/generations/{task_id}`

Возвращает унифицированный конверт задачи Uter (`code` равен `success` при успехе):

```json
{
  "code": "success",
  "message": "",
  "data": {
    "task_id": "task_xxx",
    "status": "SUCCESS",
    "progress": "100%",
    "result_url": "https://example.com/result.mp4",
    "fail_reason": "",
    "submit_time": 1699990000,
    "start_time": 1699990010,
    "finish_time": 1699990200,
    "properties": {},
    "data": {}
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `code` | string | `success` при успехе; иное значение — код ошибки |
| `data.task_id` | string | ID задачи |
| `data.status` | string | `NOT_START` / `SUBMITTED` / `QUEUED` / `IN_PROGRESS` / `SUCCESS` / `FAILURE` |
| `data.progress` | string | Прогресс, например `45%` |
| `data.result_url` | string | URL результата после успешного завершения |
| `data.fail_reason` | string | Причина сбоя |
| `data.properties` | object | Снимок отправленных параметров (модель, длительность, разрешение…) |
| `data.data` | object | Исходный результат провайдера |

Отсутствующая задача или задача другого пользователя возвращает `400` (`task_not_exist`).

## Формат видео OpenAI

`POST` `/v1/videos` принимает `application/json` и `multipart/form-data` с полями OpenAI Videos: `model`, `prompt`, `seconds`, `size`, `input_reference` и др. Ответ — объект видео OpenAI:

```json
{
  "id": "task_xxx",
  "object": "video",
  "model": "sora-2",
  "status": "queued",
  "progress": 0,
  "created_at": 1699990000,
  "seconds": "8",
  "size": "1280x720"
}
```

Сопутствующие эндпоинты:

| Метод и путь | Описание |
|---|---|
| `GET /v1/videos/{id}` | Опрос задачи; при успехе возвращает `completed_at` и финальный `status` |
| `GET /v1/videos/{id}/content` | Загрузка видеопотока через прокси; возвращает `404` для отсутствующей задачи |
| `POST /v1/videos/{id}/remix` | Повторная генерация на основе существующего видео (remix) с возвратом нового объекта |

Обратите внимание на разницу в кодах состояния: `GET /v1/videos/{id}/content` возвращает `404` для неизвестной задачи, а универсальный запрос задачи `GET /v1/video/generations/{task_id}` возвращает `400 task_not_exist`.

Значения `status`: `queued`, `in_progress`, `completed`, `failed`.
