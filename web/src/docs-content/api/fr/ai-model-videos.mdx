# Vidéo (Videos)

La génération de vidéos est asynchrone : soumettez une tâche, interrogez son état, puis récupérez le résultat. Uter expose deux entrées :

- **Format de tâche générique** : `/v1/video/generations` renvoie un `task_id` ; les options propres au fournisseur vont dans `metadata`.
- **Format vidéo OpenAI** : `/v1/videos` accepte les champs OpenAI Videos. Pour un modèle lié à un plugin de tâche `openai_video`, la requête comme la réponse suivent l'API OpenAI Videos et le SDK officiel fonctionne tel quel. Pour les modèles non revendiqués par un tel plugin, la requête revient au relais de tâche générique et la réponse utilise l'enveloppe de tâche ci-dessous (`task_id`, `status: queued`) au lieu d'un objet vidéo OpenAI.

Les champs de requête varient selon le fournisseur ; consultez aussi la page de format correspondante ci-dessous.

## Créer une tâche de génération vidéo

`POST` `/v1/video/generations`

### Corps de requête (`application/json`)

| Champ | Type | Obligatoire | Description |
|---|---|---|---|
| `model` | string | Oui | ID du modèle vidéo, issu de `GET /v1/models` ; détermine aussi le canal et la facturation |
| `prompt` | string | Non | Prompt textuel |
| `image` | string | Non | Image de première image (URL ou Base64) |
| `images` | array&lt;string&gt; | Non | Images de référence multiples (selon le modèle) |
| `duration` | number | Non | Durée en secondes ; la limite dépend du modèle |
| `size` | string | Non | Résolution, par exemple `1280x720` |
| `metadata` | object | Non | Options du fournisseur : `negative_prompt`, `seed`, `fps`, etc. |
| `user` | string | Non | Identifiant utilisateur fourni par l'appelant, pour le suivi uniquement |

### Réponse

| Statut | Signification |
|---|---|
| `200` | Tâche acceptée |
| `400` | Requête invalide (model absent, durée hors limite…) |
| `403` | Quota insuffisant |
| `429` | Concurrence amont saturée |
| `503` | Modèle inconnu ou aucun canal disponible dans le groupe courant |

#### Champs `200`

| Champ | Type | Description |
|---|---|---|
| `id` | string | ID de la tâche (identique à `task_id`) |
| `task_id` | string | ID de la tâche |
| `status` | string | État initial, généralement `queued` |
| `model` | string | Modèle réellement utilisé |
| `created_at` | integer | Date de création (secondes Unix) |

Certains fournisseurs rendent la réponse directement depuis un plugin de tâche ; les champs suivent alors leur page dédiée.

## Interroger une tâche vidéo

`GET` `/v1/video/generations/{task_id}`

Renvoie l'enveloppe de tâche unifiée de Uter (`code` vaut `success` en cas de succès) :

```json
{
  "code": "success",
  "message": "",
  "data": {
    "task_id": "task_xxx",
    "status": "SUCCESS",
    "progress": "100%",
    "result_url": "https://example.com/result.mp4",
    "fail_reason": "",
    "submit_time": 1699990000,
    "start_time": 1699990010,
    "finish_time": 1699990200,
    "properties": {},
    "data": {}
  }
}
```

| Champ | Type | Description |
|---|---|---|
| `code` | string | `success` en cas de succès ; toute autre valeur est un code d'erreur |
| `data.task_id` | string | ID de la tâche |
| `data.status` | string | `NOT_START` / `SUBMITTED` / `QUEUED` / `IN_PROGRESS` / `SUCCESS` / `FAILURE` |
| `data.progress` | string | Progression, par exemple `45%` |
| `data.result_url` | string | URL du résultat lorsque la tâche réussit |
| `data.fail_reason` | string | Motif de l'échec |
| `data.properties` | object | Instantané des paramètres soumis (modèle, durée, résolution…) |
| `data.data` | object | Résultat brut du fournisseur |

Une tâche inexistante, ou appartenant à un autre utilisateur, renvoie `400` (`task_not_exist`).

## Utiliser le format vidéo OpenAI

`POST` `/v1/videos` accepte `application/json` et `multipart/form-data` avec les champs OpenAI Videos : `model`, `prompt`, `seconds`, `size`, `input_reference`, etc. La réponse est un objet vidéo OpenAI :

```json
{
  "id": "task_xxx",
  "object": "video",
  "model": "sora-2",
  "status": "queued",
  "progress": 0,
  "created_at": 1699990000,
  "seconds": "8",
  "size": "1280x720"
}
```

Points de terminaison associés :

| Méthode et chemin | Description |
|---|---|
| `GET /v1/videos/{id}` | Interroge la tâche ; en cas de succès renvoie `completed_at` et le `status` final |
| `GET /v1/videos/{id}/content` | Télécharge le flux vidéo via le proxy ; renvoie `404` pour une tâche introuvable |
| `POST /v1/videos/{id}/remix` | Régénère à partir d'une vidéo existante (remix) et renvoie un nouvel objet vidéo |

Notez la différence de code d'état : `GET /v1/videos/{id}/content` renvoie `404` pour une tâche inconnue, tandis que la requête de tâche générique `GET /v1/video/generations/{task_id}` renvoie `400 task_not_exist`.

Valeurs de `status` : `queued`, `in_progress`, `completed`, `failed`.
