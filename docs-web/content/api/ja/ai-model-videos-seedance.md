# Seedance Format

Seedance video generation (Dreamina): call the Dreamina Seedance 2.0 model family through an asynchronous task API, supporting text-to-video, image-to-video and video continuation / editing.

## Supported Models

| Model | Description | Capabilities |
|---|---|---|
| `dreamina-seedance-2-0` | Standard Seedance 2.0, quality first | Text-to-video, image-to-video, video continuation |
| `dreamina-seedance-2-0-fast` | Fast Seedance 2.0, lower latency | Text-to-video, image-to-video, video continuation |

Both models support **video as input** (continuation / editing) by passing `video_url` inside `metadata.content`.

## Create Video

`POST` `/v1/video/generations`

### Request Headers

| Header | Required | Description |
|---|---|---|
| `Authorization` | Yes | `Bearer sk-your-api-key` |
| `Content-Type` | Yes | `application/json` |

### Request Body (`application/json`)

| Field | Type | Required | Description |
|---|---|---|---|
| `model` | string | Yes | Seedance model name, see the table above |
| `prompt` | string | Yes | Video prompt |
| `image` | string | No | Reference image for image-to-video (URL or base64 data URI); mutually exclusive with `images` |
| `images` | string[] | No | Multi-image reference (URL or base64 data URI) |
| `duration` | int | No | Length in seconds; commonly 5 / 10, default 5 |
| `seconds` | string | No | String form of `duration` (for OpenAI Sora API compatibility). Must be a plain numeric string (e.g. `"5"`, `"10"`) with no unit. Takes effect only when top-level `duration` is `0` or omitted |
| `metadata` | object | No | Seedance-specific parameters container, see "Specific Parameters" |

### Response

| Status | Description |
|---|---|
| `200` | Video task created successfully |
| `400` | Invalid request parameters |

#### `200` Response Fields

| Field | Type | Description |
|---|---|---|
| `id` / `task_id` | string | Public task ID (`task_` prefix) used for subsequent queries |
| `object` | string | Object type (`video`) |
| `model` | string | Model used |
| `status` | string | Task status (`queued` right after submission) |
| `progress` | integer | Progress percentage |
| `created_at` | integer | Creation timestamp |

> `id` / `task_id` is generated by Uter and is not the upstream task id.

## Get Video Task Status

`GET` `/v1/video/generations/{task_id}`

The response is a `{code, message, data}` envelope; on success `code` is `"success"` and `data` is the task detail object.

### Request Parameters

| Name | In | Type | Required | Description |
|---|---|---|---|---|
| `task_id` | path | string | Yes | Video task ID |

### Response

| Status | Description |
|---|---|
| `200` | Task status retrieved successfully |
| `404` | Task not found |

#### `200` Response Fields (`data`)

| Field | Type | Description |
|---|---|---|
| `data.id` | int | Internal auto-increment task ID |
| `data.task_id` | string | Public task ID (`task_` prefix) |
| `data.platform` | string | Upstream platform code |
| `data.user_id` | int | User ID |
| `data.group` | string | Group name |
| `data.channel_id` | int | Channel ID actually used |
| `data.quota` | int | Raw quota charged for this task |
| `data.action` | string | Task action, usually `generate` |
| `data.status` | string | Task status: `SUBMITTED` / `QUEUED` / `IN_PROGRESS` / `SUCCESS` / `FAILURE` |
| `data.fail_reason` | string | Failure reason (only when `status = FAILURE`) |
| `data.result_url` | string | Video result URL (returned on success only; an upstream temporary link) |
| `data.progress` | string | Progress, e.g. `"100%"` |
| `data.submit_time` / `start_time` / `finish_time` | int64 | Submit / start / finish Unix timestamps (seconds) |
| `data.properties.upstream_model_name` | string | Model name actually sent upstream |
| `data.data` | object | Raw upstream response (`usage`, `content.video_url`, `resolution`, `framespersecond`, …) |

#### Status Enum

| Status | Description |
|---|---|
| `SUBMITTED` | Submitted |
| `QUEUED` | Queued upstream |
| `IN_PROGRESS` | Generating |
| `SUCCESS` | Completed; `result_url` holds the video |
| `FAILURE` | Failed; `fail_reason` explains why |

## Get Video Content

`GET` `/v1/videos/{task_id}/content`

Returns the raw video stream (`Content-Type: video/mp4`). Uter proxies the upstream URL.

### Request Parameters

| Name | In | Type | Required | Description |
|---|---|---|---|---|
| `task_id` | path | string | Yes | Video task ID |

> **Strongly recommended**: download via the `/content` proxy rather than accessing `result_url` directly, which is an upstream temporary link with a limited lifetime.

## Specific Parameters (`metadata`)

All Seedance-specific fields are passed through the request body's `metadata` object and forwarded upstream.

### Resolution / Aspect Ratio / Duration

| Field | Type | Description |
|---|---|---|
| `resolution` | string | Resolution tier: `480p` `720p` `1080p` |
| `ratio` | string | Aspect ratio: `16:9` `9:16` `1:1` `4:3` `3:4` `21:9` `adaptive` |
| `duration` | int | Video length in seconds: `5` `10`. **Note:** top-level `duration` (or `seconds`) takes precedence over `metadata.duration` |
| `frames` | int | Frame count (optional, mutually exclusive with `duration`), e.g. `121` |
| `seed` | int | Random seed, `0` – `2^31-1` |

### Camera and Content Control

| Field | Type | Description |
|---|---|---|
| `camera_fixed` | bool | Fix the camera (`true` = static) |
| `watermark` | bool | Whether to add the official watermark |

### Advanced Parameters

| Field | Type | Description |
|---|---|---|
| `service_tier` | string | Service tier affecting speed and quota (e.g. `auto` / `default` / `priority`) |
| `execution_expires_after` | int | Task execution timeout in seconds |
| `generate_audio` | bool | Whether to generate audio |
| `draft` | bool | Draft mode (faster and cheaper, slightly lower quality) |
| `return_last_frame` | bool | Whether to return the last frame image in the response |
| `callback_url` | string | Callback URL notified on task completion |

### Multimodal Input (`content` Array)

Besides the top-level `image` / `images` fields, you can pass a multimodal input array in `metadata.content`, mixing **images** and **videos**:

| `type` | Purpose |
|---|---|
| `image_url` + `image_url.url` | Image reference (image-to-video) |
| `video_url` + `video_url.url` | Video input (continuation / editing) |

```json
{
  "model": "dreamina-seedance-2-0",
  "prompt": "Extend this video so the cat walks out of frame",
  "metadata": {
    "content": [
      { "type": "video_url", "video_url": { "url": "https://example.com/cat.mp4" } }
    ],
    "resolution": "720p"
  }
}
```

## Full Example

```bash
# Text-to-video
curl -X POST https://uter.ai/v1/video/generations \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "dreamina-seedance-2-0",
    "prompt": "A cat strolling on the lunar surface under a starry sky",
    "duration": 5,
    "metadata": { "resolution": "720p", "ratio": "16:9", "seed": 42 }
  }'

# Poll the task
curl https://uter.ai/v1/video/generations/task_xxx \
  -H "Authorization: Bearer sk-your-api-key"

# Download the video
curl https://uter.ai/v1/videos/task_xxx/content \
  -H "Authorization: Bearer sk-your-api-key" \
  -o cat_on_moon.mp4
```

## Status Codes and Errors

| Case | Description |
|---|---|
| `400` | Model not found or unauthorised (`model not allowed`), empty `prompt` (`prompt is required`), invalid resolution / duration |
| `401` / `403` | API key invalid / not allowed to access this model (check the token model whitelist) |
| `402` | Insufficient balance (`insufficient user quota`) |
| Task `FAILURE` | Upstream failure (moderation / unreachable image or video URL / upstream timeout); Uter refunds the charge automatically |

Suggested handling: adjust the prompt on moderation failures; switch to base64 when URLs are unreachable; retry later or switch to `dreamina-seedance-2-0-fast` on upstream timeouts.
