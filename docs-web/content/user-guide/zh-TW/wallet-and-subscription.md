# 錢包與訂閱

登入後點選左側導航欄的「錢包」，或直接訪問 `/wallet`，進入錢包頁面。錢包頁面集中提供餘額統計、線上充值、兌換碼、訂單歷史、訂閱計劃、我的訂閱和邀請獎勵等功能。具體顯示的區域、金額、支付方式和套餐內容由平臺配置決定。

## 檢視餘額與用量

錢包統計區域包括以下資訊：

* **當前餘額**：可用於模型呼叫或其他計費操作的內部額度，不是現金餘額。
* **累計消耗**：賬戶歷史上已使用的額度。
* **API 請求數**：賬戶發起的 API 請求數量。

<Callout type="warn">
  1. 餘額和用量的顯示單位由 Root 在「系統設定」→「計費與支付」中配置的貨幣和額度顯示規則決定。
  2. 不要根據頁面上的符號或數值自行推算固定匯率；實際扣費還會受到模型、分組、渠道和例項計費規則影響。
</Callout>

## 線上充值

如果平臺啟用了線上支付，錢包的充值區域會顯示可用的充值選項。充值金額、預設金額、最低充值金額、折扣和匯率均由平臺配置決定。

1. 在「充值」區域選擇頁面提供的預設金額，或輸入自定義金額。
2. 檢視系統計算的充值額度和應付金額。
3. 選擇當前平臺提供的支付方式。
4. 在確認視窗核對充值額度、應付金額、折扣和支付方式。
5. 確認後跳轉到第三方支付頁面完成付款。
6. 支付完成後返回錢包，等待訂單狀態和餘額更新。

<Callout type="warn">
  1) 專案程式碼支援 EPay、Stripe、Creem、Waffo 和 Waffo Pancake 等支付閘道器，但只有已啟用、配置完整且當前可用的支付方式才會顯示。不同閘道器還可能有額外的金額或支付限制，請以頁面提示為準。沒有可用支付方式時，請聯絡平臺管理員。
  2) 支付成功需要第三方支付回撥完成訂單確認，付款後餘額不一定立即更新。遇到支付成功但餘額未變化的情況，請先保留訂單號並聯系管理員，不要重複支付。
  3) 支付方式、最低充值金額、折扣、匯率和預設金額不是 優特 的固定值，不能根據其他例項或示例頁面推斷當前例項的規則。
</Callout>

## 兌換碼

當兌換碼可用時，充值區域會顯示兌換碼輸入框；如果管理員配置了兌換碼獲取地址，頁面還會顯示相應的外部連結。

1. 在充值區域找到「兌換碼」輸入框。
2. 輸入管理員提供的兌換碼。
3. 點選「兌換」，等待結果提示並重新整理餘額。

<Callout type="info">
  1) 兌換碼必須滿足平臺配置的有效期和使用規則，並且處於啟用狀態、尚未使用。每個兌換碼只能成功使用一次。
  2) 兌換失敗時，頁面可能不會顯示“已使用”“已過期”或“不存在”等具體原因，請檢查兌換碼是否完整，並向管理員確認其狀態。
  3) 如果平臺尚未完成相關支付合規配置，兌換碼輸入和兌換操作會被禁用，頁面會顯示相應提示。
</Callout>

## 訂閱計劃

訂閱計劃位於錢包頁面的訂閱區域。只有啟用且當前平臺透過支付合規檢查的計劃才會由介面返回並顯示；沒有可用計劃時，訂閱區域不顯示。

套餐卡包含以下資訊：

| 專案     | 說明                                                          |
| ------ | ----------------------------------------------------------- |
| 標題和副標題 | 管理員為套餐設定的名稱和說明。                                             |
| 價格     | 購買套餐所需的金額，具體數值由例項配置決定。                                      |
| 有效期    | 可按年、月、天、小時或自定義時長(秒)配置。                                      |
| 總額度    | 套餐包含的訂閱額度；配置為 0 時表示不限總額度。                                   |
| 額度重置   | 可配置為不重置、每日、每週、每月或自定義週期。                                     |
| 購買上限   | 限制同一使用者可購買的次數；配置為 0 時表示不限制次數。                                |
| 升級分組   | 購買成功後可能切換到管理員配置的分組。                                         |
| 降級分組   | 訂閱到期後可能切換到管理員配置的分組；未設定時，只有購買時透過升級分組切換且到期時仍處於該分組，才通常恢復購買前分組。 |

<Callout type="warn">
  「不限總額度」只表示該訂閱本身不設定總額度上限，並不代表可以無限制呼叫。請求仍會受到模型、路由、分組和計費規則限制。
</Callout>

## 購買訂閱套餐

1. 開啟錢包頁面的訂閱區域。
2. 選擇套餐並檢視有效期、額度、重置週期和購買限制。
3. 選擇頁面顯示的購買方式。
4. 核對訂單資訊後完成餘額扣款或第三方支付。
5. 使用第三方支付時，返回錢包並等待支付回撥；狀態更新後再確認訂閱是否生效。

可用的購買方式取決於全域性支付閘道器和套餐本身的配置，可能包括：

* **錢包餘額**：套餐允許餘額支付且賬戶餘額足夠時可用。扣除額度按“套餐價格 × `QuotaPerUnit`”計算並向上取整，具體單位由平臺配置決定。
* **EPay**：需要平臺啟用 EPay 支付，並且當前支付配置可用。
* **Stripe、Creem 或 Waffo Pancake**：除全域性閘道器可用外，套餐還必須配置對應的支付產品。

<Callout type="warn">
  普通 Waffo 支付方式用於線上充值時，不代表它支援訂閱購買。達到使用者購買上限、套餐被停用、支付方式不可用或餘額不足時，購買按鈕可能被禁用或操作失敗。
</Callout>

## 檢視訂閱狀態

「我的訂閱」區域會顯示當前訂閱和歷史狀態，常見狀態包括：

* **Active**：訂閱正在生效，頁面會顯示剩餘天數和結束時間；如果配置了下次重置時間，還會顯示該時間；對於有限額度訂閱，還會顯示總額度、已用額度、剩餘額度和使用進度。
* **Expired**：訂閱已到期，不能再使用該訂閱額度。
* **Cancelled**：訂閱已被取消或提前失效。使用者端沒有自助取消入口，此狀態通常由管理員操作產生。

<Callout type="info">
  1. 達到額度重置時間後，有限額度訂閱的已用額度會清零，並開始新的額度週期。若下一次重置時間已經超過訂閱結束時間，則不會再設定該次重置。
  2. 訂閱到期後的分組由套餐配置決定：如果設定了降級分組，通常會切換到該分組；未設定時，只有購買時透過升級分組切換、且到期時仍處於該升級分組，才通常回到購買前分組。若沒有發生升級，或賬戶中仍有其他活動升級訂閱，則可能保持當前分組；最終分組會結合其他訂閱狀態處理。
  3. 當前無自動續費訂閱套餐功能，訂閱到期後如需繼續使用，請重新購買套餐。
</Callout>

## 選擇計費偏好

錢包頁面可以選擇請求的額度扣除順序。儲存偏好後，後端會按照以下規則處理：

| 計費偏好     | 扣除規則                                                         |
| -------- | ------------------------------------------------------------ |
| **優先訂閱** | 有活動訂閱時先扣訂閱；訂閱額度不足時，只有所有活動訂閱都允許回退錢包，才會使用錢包。 沒有活動訂閱時使用錢包。 |
| **優先錢包** | 先扣錢包；錢包餘額不足時再嘗試使用訂閱。                                         |
| **僅用訂閱** | 只使用訂閱。沒有活動訂閱或訂閱額度不足時，請求失敗，不會切換到錢包。                           |
| **僅用錢包** | 只使用錢包。餘額不足時請求失敗，不會使用訂閱。                                      |

<Callout type="info">
  套餐的「錢包溢位回退」規則會影響“優先訂閱”的結果：只要有一個活動訂閱禁止回退，訂閱額度不足時就不能轉用錢包。沒有活動訂閱時，頁面會禁用“優先訂閱”和“僅用訂閱”選項。
</Callout>

## 邀請獎勵

錢包頁面的邀請獎勵區域會顯示邀請連結、待轉入獎勵、歷史累計獎勵和邀請人數。邀請碼嵌在邀請連結的 `aff` 引數中，連結格式為：

```text
当前站点地址/sign-up?aff=<邀请码>
```

使用流程：

1. 在邀請獎勵區域複製邀請連結。
2. 將連結傳送給新使用者，由對方透過連結註冊賬號；賬號密碼註冊及使用 OAuth 狀態流程的部分新使用者註冊會讀取該引數，微信、Telegram 等獨立登入流程不適用。
3. 滿足平臺配置的邀請條件後，獎勵會按照規則發放。
4. 邀請人的獎勵通常先進入待轉入獎勵；待獎勵達到可轉移條件後，點選「轉入餘額」將其加入主餘額。

<Callout type="warn">
  * 被邀請使用者的獎勵（如果平臺啟用）會直接加入其賬戶額度；邀請人的獎勵通常先進入待轉入獎勵。
  * 邀請獎勵的金額、發放條件和最低轉移量由平臺配置決定。
  * 轉入餘額支援部分轉移，但不能超過當前待轉獎勵，且不能低於平臺額度單位要求；這不是現金提現、退款或提現申請。
  * 如果支付合規狀態未滿足要求，獎勵可能不會發放，「轉入餘額」操作也可能不可用。
  * 無效邀請碼不會阻止註冊，已註冊使用者也不會因為重複使用邀請碼再次獲得獎勵。
</Callout>

## 訂單歷史

* 點選充值卡右上角的「訂單歷史」可以檢視充值和支付訂單記錄。
* 頁面支援按訂單號搜尋和分頁，並顯示訂單號、建立時間、支付方式、充值額度或金額、支付金額和訂單狀態。

<Callout type="info">
  1. 普通使用者只能查詢自己最近 30 天的記錄，搜尋條件只匹配訂單號。
  2. 該列表主要用於檢視充值和支付訂單，不保證涵蓋所有訂閱訂單。
</Callout>

## 常見限制

以下情況可能導致錢包或訂閱相關功能不可用：

1. 平臺未配置支付閘道器或支付產品，導致沒有可用的支付方式或訂閱套餐。
2. 支付合規狀態尚未滿足要求，導致支付方式或訂閱計劃不可用，兌換碼操作顯示為禁用狀態。
3. 充值金額低於平臺或閘道器要求的最低金額。
4. 餘額不足、套餐已停用或達到個人購買上限。
5. 第三方支付尚未完成回撥，訂單仍處於處理中。

<Callout type="warn">
  遇到支付成功但訂單或餘額長時間未更新時，請保留訂單號、支付憑證和發生時間，聯絡平臺管理員核查，不要重複支付。
</Callout>
