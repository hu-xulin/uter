# 日誌與非同步任務

* 優特 將請求明細、繪圖記錄和影片、音樂等非同步任務分別儲存。
* 登入後，可以從左側導航進入「使用日誌」或「任務日誌」。
* 本頁統一說明三個資料分割槽、任務狀態和介面查詢方式。

三個分割槽對應以下路徑：

* `/usage-logs/common`：通用 API 使用日誌和計費明細；
* `/usage-logs/drawing`：Midjourney 繪圖任務；
* `/usage-logs/task`：Suno、影片等通用非同步任務。

<Callout type="info">
  普通使用者只能檢視自己的記錄。Admin 和 Root 可以在頁面右上角切換「全部」與「僅自己」；切換為「僅自己」後，頁面按普通使用者的欄位和許可權返回資料。
</Callout>

## 使用日誌

* 在左側邊欄點選「使用日誌」或訪問 `/usage-logs/common` 檢視 API 請求和計費明細。

### 篩選記錄

使用日誌記錄查詢可用篩選項如下：

| 篩選項               | 說明                         |
| ----------------- | -------------------------- |
| 時間範圍              | 按記錄建立時間篩選，起止時間都包含在查詢範圍內。   |
| 模型名稱              | 按模型名稱篩選。                   |
| 分組                | 按請求使用的分組篩選。                |
| 日誌型別              | 所有型別、充值、消耗、管理、系統、錯誤、退款、登入。 |
| 令牌名稱              | 按 API 金鑰名稱篩選。              |
| 請求ID              | 按 優特 請求 ID 定位一次請求。    |
| 上游請求ID            | 按上游服務返回或記錄的請求 ID 定位請求。     |
| 使用者名稱（僅Admin/Root）  | 在管理員檢視中按使用者名稱篩選。             |
| 渠道ID（僅Admin/Root） | 在管理員檢視中按渠道 ID 篩選。          |

### 頁面統計

篩選欄中的統計值與當前許可權和篩選條件相關：

* **Usage**：彙總消費記錄的額度，可根據時間、模型、分組、金鑰、渠道和使用者條件進行篩選。
* **RPM**：最近 60 秒內的消費請求數。
* **TPM**：最近 60 秒內的輸入 Token 與輸出 Token 總數。

### 列表與詳情

* 普通使用者可以看到時間和型別、令牌、模型、流、Tokens、費用、耗時和詳情列。
* Admin/Root 檢視還可顯示渠道和使用者列。

<img alt="使用日誌頁" src="01-usage-logs.webp" />

<Callout type="info">
  1. **Tokens**：顯示輸入 Token / 輸出 Token；使用快取時還可能顯示快取讀取和寫入數量。
  2. **費用**：顯示該條記錄的額度消耗或退款結果，具體格式取決於例項的額度顯示方式。
  3. **耗時**：對有計時資料的消費或錯誤記錄顯示響應耗時；流式請求可能額外顯示首字響應時間（FRT）和吞吐資訊。
  4. **詳情**：點選記錄可開啟詳情對話方塊。根據日誌型別和記錄中實際儲存的欄位，可能包含請求 ID、模型對映、錯誤或退款原因、Token 明細、計費明細、快取/音訊/圖片用量、流狀態等，不是每條記錄都會顯示全部區塊。
  5. 管理員在詳情中還可能看到渠道重試鏈、請求轉換、計費路徑、充值審計或管理操作審計等資訊。
</Callout>

<Callout type="warn">
  * **為什麼看不到某條記錄？**
    消費日誌是否寫入受平臺的「系統設定」 → 「運維」 → 「日誌維護」 → 「記錄配額使用量」開關控制，Root 關閉該設定後，新的消費記錄可能不會產生。錯誤日誌還受錯誤日誌開關和可記錄錯誤型別限制，並非每個失敗響應都會生成 Error 記錄。使用者個人資料中的「記錄 IP 地址」偏好只控制消費日誌和錯誤請求日誌是否儲存請求 IP；登入、管理審計和充值等其他日誌可能按各自的審計流程記錄 IP。
</Callout>

## 任務日誌

* 「任務日誌」包括「繪圖日誌」和「任務日誌」。

1. 「繪圖日誌」：記錄Midjourney繪畫任務日誌。
2. 「任務日誌」：記錄文生影片、圖生影片、音訊生成等非同步任務日誌。

## 繪圖日誌

* 在左側邊欄點選「任務日誌」 → 「繪圖日誌」或訪問 `/usage-logs/drawing` 檢視 Midjourney 繪圖任務記錄。
* 普通使用者只能檢視自己的任務；Admin/Root 可以在「全部」檢視檢視管理範圍內的任務，並可額外檢視渠道和提交結果。

繪圖日誌支援按以下條件篩選：

1. 日期範圍；
2. Midjourney 任務 ID；
3. 渠道 ID（僅Admin/Root）。

<img alt="繪圖日誌頁" src="02-drawing-logs.webp" />

<Callout type="info">
  1. 列表包含提交時間和狀態、渠道 ID（僅Admin/Root）、操作型別、任務 ID、耗時、提交結果、進度、圖片、提示詞和失敗原因。點選圖片可開啟預覽；點選提示詞可檢視完整內容；點選失敗原因可檢視完整錯誤資訊。
  2. 繪圖狀態包括：未啟動、佇列中、執行中、成功、失敗、視窗等待。
  3. 繪圖狀態由後臺輪詢上游任務更新。輪詢存在間隔，任務狀態可能存在延遲；當後臺取得對應的上游任務資料時，系統會將已提交超過約 1 小時且仍未完成的 Midjourney 任務標記為失敗。
</Callout>

## 任務日誌（非同步任務日誌）

* 在左側邊欄點選「任務日誌」 → 「任務日誌」或訪問 `/usage-logs/task` 檢視非同步任務日誌。普通使用者只能檢視自己的任務；Admin/Root 檢視還會顯示渠道ID和使用者。
* 影片、音樂等非同步介面不會在提交請求時立即返回最終結果。提交成功後，優特 會返回對外公開的任務 ID，並儲存任務記錄，再由後臺輪詢上游服務並更新狀態、進度和結果。

### 篩選任務

任務日誌支援按以下條件篩選：

1. 日期範圍；
2. 任務 ID；
3. 渠道 ID (僅Admin/Root)。

### 列表與結果

任務列表顯示提交時間和完成時間、渠道、使用者、任務 ID、平臺與操作、耗時、狀態、進度和詳情：

* Suno 任務成功且返回音訊地址時，詳情列提供音訊預覽；
* 部分影片任務在成功後會顯示預覽入口；也可以使用同一賬號的登入會話或 API 金鑰請求 `/v1/videos/{task_id}/content` 獲取已完成任務的影片內容。該介面會校驗任務歸屬，任務未完成或不屬於當前使用者時不會返回內容；
* 其他失敗記錄會在詳情列顯示失敗原因，點選後可檢視完整資訊。

## 任務狀態與後臺處理

非同步任務日誌使用以下狀態值。不同平臺介面卡有時會保留上游狀態的大小寫或平臺差異，因此介面返回值應以實際任務記錄為準：

| 狀態    | 含義                        |
| ----- | ------------------------- |
| `未启动` | 任務記錄已建立，但尚未開始處理。          |
| `队列中` | 已提交到上游，等待後續處理。            |
| `排队中` | 已進入處理佇列。                  |
| `执行中` | 正在處理。                     |
| `成功`  | 已完成，可以檢視或獲取結果。            |
| `失败`  | 處理失敗；失敗原因會寫入任務記錄（如果上游提供）。 |
| `未知`  | 內部定義的未知狀態兜底值。             |

<img alt="任務日誌頁" src="03-task-logs.webp" />

<Callout type="info">
  任務狀態由後臺輪詢更新，剛提交的任務狀態可能存在延遲。預設非同步任務輪詢約每 15 秒檢查一次；輪詢只會在 `UPDATE_TASK` 啟用且存在未完成任務時執行。非同步任務超時閾值由 `TASK_TIMEOUT_MINUTES` 控制，預設是 1440 分鐘，設為 `0` 可禁用超時處理。
</Callout>

### 失敗、超時與退款

任務進入失敗終態後，若任務有提交階段預扣的額度，系統通常會嘗試退還，並在退款成功時寫入一條 `退款` 日誌。退款成功後會清除任務記錄中的待退款額度，並回減使用者和渠道的累計用量；請求次數不會因此回退。

<Callout type="warn">
  以下情況可能導致頁面狀態與餘額暫時不一致：

  1. 任務沒有預扣額度（`quota = 0`）；
  2. 資金來源退款失敗，系統會保留任務額度以便重試或人工對賬；

  * 排查退款時，請同時檢視錢包餘額或訂閱剩餘額度（以及使用中的 API 金鑰額度）和通用使用日誌中的「退款」記錄。不要僅根據「失敗」狀態判斷退款是否已經完成。
</Callout>

## 介面參考

### 日誌查詢介面

如果使用 API 而不是控制檯，可以呼叫以下只讀介面。介面仍受認證和許可權限制，普通使用者的結果會強制限定為當前賬號：

| 資料            | 管理員介面               | 使用者介面                     | 時間引數單位            |
| ------------- | ------------------- | ------------------------ | ----------------- |
| 通用日誌          | `GET /api/log/`     | `GET /api/log/self`      | 秒（`created_at`）   |
| 日誌統計          | `GET /api/log/stat` | `GET /api/log/self/stat` | 秒                 |
| Midjourney 繪圖 | `GET /api/mj/`      | `GET /api/mj/self`       | 毫秒（`submit_time`） |
| 非同步任務          | `GET /api/task/`    | `GET /api/task/self`     | 秒（`submit_time`）  |

日誌和任務列表介面使用分頁引數 `p` 和 `page_size`；頁碼從 `1` 開始，使用正常正整數時，超過 `100` 的 `page_size` 會被截為 `100`。使用者日誌的總數統計還受到例項內部查詢上限影響。任務返回資料不會包含可能含有金鑰、上游任務標識或計費上下文的私有欄位。

另外，`GET /api/log/token` 可使用 API 金鑰讀取該金鑰最近的日誌。該介面採用只讀令牌認證：會校驗金鑰存在、金鑰未被明確禁用且所屬使用者可用，但不會因金鑰過期或額度耗盡而拒絕查詢；最多返回最近 `1000` 條記錄。

任務列表介面的常用查詢引數如下：

| 範圍         | 方法和路徑                | 常用查詢引數                                                                                        |
| ---------- | -------------------- | --------------------------------------------------------------------------------------------- |
| 當前使用者       | `GET /api/task/self` | `p`、`page_size`、`task_id`、`start_timestamp`、`end_timestamp`；也接受 `platform`、`action`、`status`。 |
| Admin/Root | `GET /api/task/`     | 在使用者介面引數基礎上增加 `channel_id`，並可按 `platform`、`action`、`status` 篩選。                                |

<Callout type="info">
  任務介面的 `start_timestamp`、`end_timestamp` 使用 Unix 秒時間戳；Midjourney 繪圖介面的時間引數使用毫秒。
</Callout>

| 介面              | 路徑                                                                                                   | 說明                                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| OpenAI 影片生成     | `POST /v1/videos`                                                                                    | 建立 OpenAI 相容的影片生成非同步任務，成功後返回任務標識。                                                                             |

## 與資料看板的關係

* 日誌是逐條明細，資料看板是按時間、模型、使用者或渠道聚合後的統計。
* 兩者的篩選範圍、重新整理時機和統計口徑可能不同；
* 新請求先出現在日誌中，圖表資料可能需要等待聚合或重新整理後才更新。

<Callout type="info">
  排查一次呼叫時，建議先在通用日誌中按時間、模型、Request ID 或 Upstream Request ID 定位請求；非同步請求則記錄提交介面返回的 `task_id`，再查詢任務最終狀態和失敗詳情。若任務長時間沒有變化，檢查渠道可用性、任務輪詢開關、超時設定以及對應的「退款」日誌。
</Callout>
