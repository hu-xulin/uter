# ウォレットとサブスクリプション

ログイン後、左ナビゲーションバーの「Wallet」をクリックするか、`/wallet` に直接アクセスすると、ウォレットページを開けます。ウォレットページでは、残高の統計、オンラインチャージ、引き換えコード、注文履歴、サブスクリプションプラン、自分のサブスクリプション、招待特典などの機能が一元的に提供されています。表示される項目、金額、支払い方法、プランの内容は、プラットフォームの設定によって決まります。

## 残高と利用状況の確認

ウォレットの統計エリアには、次の情報が含まれます：

* **現在の残高**：モデル呼び出しやその他の課金操作に使用できる内部クォータであり、現金残高ではありません。
* **累計消費**：このアカウントがこれまでに使用したクォータです。
* **API リクエスト**：このアカウントが発行した API リクエストの数です。

<Callout type="warn">
  1. 残高と利用状況の表示単位は、Root が「System Settings」→「Billing and Payments」で設定した通貨とクォータの表示ルールによって決まります。
  2. ページ上の記号や数値から固定の為替レートを推測しないでください。実際の減算は、モデル、グループ、チャネル、インスタンスの課金ルールにも影響されます。
</Callout>

## オンラインチャージ

プラットフォームでオンライン決済が有効になっている場合、ウォレットのチャージエリアに表示可能なチャージオプションが表示されます。チャージ金額、プリセット金額、最低チャージ金額、割引、為替レートは、すべてプラットフォームの設定によって決まります。

1. 「チャージ」エリアで、ページに表示されているプリセット金額を選択するか、カスタム金額を入力します。
2. システムが計算したチャージクォータと支払金額を確認します。
3. 現在のプラットフォームが提供する支払い方法を選択します。
4. 確認ウィンドウで、チャージクォータ、支払金額、割引、支払い方法を確認します。
5. 確認後、サードパーティの支払いページに移動して支払いを完了します。
6. 支払いが完了したらウォレットに戻り、注文状態と残高が更新されるまでお待ちください。

<Callout type="warn">
  1) 当プロジェクトのコードは EPay、Stripe、Creem、Waffo、Waffo Pancake などの決済ゲートウェイに対応していますが、有効化され完全に設定され、現在利用可能な支払い方法だけが表示されます。ゲートウェイによっては、金額や支払いに関する追加の制限がかかる場合があります。ページ上の注意書きに従うか、プラットフォーム管理者へお問い合わせください。
  2) 支払いの成功には、サードパーティの決済コールバックによる注文の確認が必要です。支払い直後に残高が更新されない場合があります。支払いは成功しているのに残高が変わらない場合は、注文番号を控え、管理者に連絡してください。二重支払いはしないでください。
  3) 支払い方法、最低チャージ金額、割引、為替レート、プリセット金額は Uter の固定値ではありません。他のインスタンスやサンプルページから現在のインスタンスのルールを推測することはできません。
</Callout>

## 引き換えコード

引き換えコードが利用可能な場合、チャージエリアに引き換えコードの入力欄が表示されます。管理者が引き換えコードの取得アドレスを設定している場合、ページには対応する外部リンクも表示されます。

1. チャージエリアにある「Redemption Code」入力欄を探します。
2. 管理者が提供する引き換えコードを入力します。
3. 「Redeem」をクリックし、結果の表示を待ってから、残高を再確認します。

<Callout type="info">
  1) 引き換えコードは、プラットフォームが設定した有効期間と利用ルールを満たし、有効化されていて未使用である必要があります。各引き換えコードは 1 回のみ成功地利用できます。
  2) 引き換えに失敗した場合、ページに「使用済み」「期限切れ」「存在しません」など理由が表示されないことがあります。引き換えコードが完全か確認し、管理者に状態を確認してください。
  3) プラットフォームが関連する決済コンプライアンス設定を完了していない場合、引き換えコードの入力と引き換え操作は無効になり、ページには該当する注意書きが表示されます。
</Callout>

## サブスクリプションプラン

サブスクリプションプランは、ウォレットページのサブスクリプションエリアにあります。現在のプラットフォームで有効化され、決済コンプライアンスの確認を通過したプランだけが API から返され、表示されます。利用できるプランがない場合、サブスクリプションエリアは表示されません。

プランカードには、次の情報が含まれます：

| 項目 | 内容 |
|---|---|
| タイトルとサブタイトル | 管理者がプランに設定した名称と説明。 |
| 価格 | プランの購入に必要な金額。実際の値はインスタンスの設定によって決まります。 |
| 有効期間 | 年、月、日、時間、または任意の期間（秒）で設定できます。 |
| 合計クォータ | プランに含まれるサブスクリプションクォータ。0 に設定すると合計クォータ無制限を意味します。 |
| クォータリセット | リセットしない、毎日、毎週、毎月、または任意のサイクルから設定できます。 |
| 購入上限 | 同じユーザーが購入できる回数の上限。0 に設定すると無制限です。 |
| アップグレードグループ | 購入成功後に、管理者が設定したグループへ切り替えられる場合があります。 |
| ダウングレードグループ | サブスクリプションの有効期限が切れた後に、管理者が設定したグループへ切り替えられる場合があります。設定がない場合は、購入時にアップグレードグループ経由で切り替わり、かつ有効期限切れ時点でもそのグループにいる場合に限り、通常は購入前のグループに戻ります。 |

<Callout type="warn">
  「合計クォータ無制限」は、サブスクリプションそのものに合計クォータの上限を設けない다는意味であり、呼び出し回数が無制限であることを意味しません。リクエストは依然として、モデル、ルーティング、グループ、課金のルールに従います。
</Callout>

## サブスクリプションプランの購入

1. ウォレットページのサブスクリプションエリアを開きます。
2. プランを選択し、その有効期間、クォータ、リセットサイクル、購入上限を確認します。
3. ページに表示されている購入方法を選択します。
4. 注文情報を確認したうえで、残高からの減算またはサードパーティ決済を完了します。
5. サードパーティ決済を利用する場合はウォレットに戻り、決済コールバックを待ってください。状態が更新された後にサブスクリプションが有効になっているかを確認します。

利用できる購入方法は、グローバルな決済ゲートウェイとプランそのものの設定によって異なり、次のようなものが含まれます：

* **ウォレット残高**：プランが残高での支払いを許可し、アカウント残高が十分である場合利用できます。減算されるクォータは「プラン価格 × `QuotaPerUnit`」を計算して切り上げた値で、実際の単位はプラットフォームの設定によって決まります。
* **EPay**：プラットフォームが EPay 決済を有効にし、現在の決済設定が利用可能な場合に必要です。
* **Stripe、Creem、Waffo Pancake**：グローバルなゲートウェイが利用可能な加え、プランにも対応する決済製品が設定されている必要があります。

<Callout type="warn">
  オンラインチャージで通常の Waffo 支払い方法を利用できることは、サブスクリプションの購入に対応 있다는意味ではありません。ユーザー購入上限に達した、プランが無効化された、支払い方法が利用できない、残高が不足しているなどの場合、購入ボタンは無効になるか、操作が失敗することがあります。
</Callout>

## サブスクリプション状態の確認

「My Subscriptions」エリアでは、現在および過去のサブスクリプション状態を表示します。主な状態は次のとおりです：

* **有効**：サブスクリプションが有効です。ページには残り日数と終了時刻が表示され、次回のリセット時刻が設定されている場合はそれも表示されます。クォータが限定されているサブスクリプションでは、合計クォータ、使用済みクォータ、残りのクォータ、利用状況も表示されます。
* **期限切れ**：サブスクリプションの有効期限が切れ、サブスクリプションクォータは使用できなくなりました。
* **キャンセル済み**：サブスクリプションがキャンセルされた、または事前に無効化されました。ユーザー側に自己申告でキャンセルできる入口はありません。通常、この状態は管理者操作によって発生します。

<Callout type="info">
  1. クォータのリセット時刻に達すると、クォータが限定されているサブスクリプションの使用済みクォータはクリアされ、新しいクォータサイクルが開始します。次のリセット時刻がサブスクリプションの終了時刻を過ぎている場合、そのリセットは設定されません。
  2. サブスクリプション期限切れ後のグループは、プランの設定によって決まります。ダウングレードグループが設定されている場合は通常そのグループに切り替わります。設定がない場合は、購入時にアップグレードグループ経由で切り替わり、かつ有効期限切れ時点でもそのアップグレードグループにいる場合に限り、通常は購入前のグループに戻ります。アップグレードが発生していない場合や、アカウントに他の有効なアップグレードサブスクリプションがある場合は、現在のグループが維持されることがあります。最終的なグループは、他のサブスクリプション状態と併せて処理されます。
  3. 現在、サブスクリプションプランには自動更新機能はありません。期限切れ後もサブスクリプションを使用したい場合は、プランを再購入してください。
</Callout>

## 課金優先順位の選択

ウォレットページでは、リクエストに対するクォータの減算順序を選択できます。設定を保存すると、バックエンドは次のルールに従って処理します。

| 課金優先順位 | 減算ルール |
|---|---|
| **サブスクリプション優先** | 有効なサブスクリプションから先に減算します。サブスクリプションクォータが不足する場合、すべての有効なサブスクリプションがウォレットへのフォールバックを許可している場合にのみウォレットを使用します。有効なサブスクリプションがない場合はウォレットを使用します。 |
| **ウォレット優先** | まずウォレットから減算します。ウォレット残高が不足する場合に限り、サブスクリプションの使用を試みます。 |
| **サブスクリプションのみ** | サブスクリプションのみを使用します。有効なサブスクリプションがない場合、またはサブスクリプションクォータが不足する場合、リクエストは失敗し、ウォレットには切り替わりません。 |
| **ウォレットのみ** | ウォレットのみを使用します。残高が不足する場合、リクエストは失敗し、サブスクリプションは使用しません。 |

<Callout type="info">
  プランの「ウォレット超過フォールバック」ルールは、「サブスクリプション優先」の結果に影響します。有効なサブスクリプションのうち 1 つでもフォールバックを禁止している場合、サブスクリプションクォータが不足していてもウォレットは使用できません。有効なサブスクリプションがない場合、ページでは「サブスクリプション優先」と「サブスクリプションのみ」が無効になります。
</Callout>

## 招待特典

ウォレットページの招待特典エリアには、招待リンク、保留中の特典、累計獲得特典、招待者の人数が表示されます。招待コードは招待リンクの `aff` パラメータに埋め込まれており、リンクの形式は次のとおりです：

```text
当前站点地址/sign-up?aff=<邀请码>
```

利用手順：

1. 招待特典エリアの招待リンクをコピーします。
2. そのリンクを新しいユーザーに送り、リンク経由でアカウントを登録してもらいます。アカウントパスワード登録や OAuth の一部フローではこのパラメータが読み込まれますが、WeChat や Telegram のような独立したログインフローには適用されません。
3. プラットフォームが設定した招待条件を満たすと、ルールに従って特典が配布されます。
4. 招待者の特典は通常、まず保留中の特典に入ります。特典が振替条件を満たしたら、「Transfer to Balance」をクリックして主な残高に加えます。

<Callout type="warn">
  * 招待されたユーザーの特典（プラットフォームで有効になっている場合）は、直接そのアカウントのクォータに加算されます。招待者の特典は通常、まず保留中の特典に入ります。
  * 招待特典の金額、配布条件、最低振替金額は、プラットフォームの設定によって決まります。
  * 残高への振替は一部振替に対応していますが、現在の保留中特典を超えることはできず、プラットフォームのクォータ単位の要件より少なくすることもできません。これは現金引き出し、返金、出金申請ではありません。
  * 決済コンプライアンスの状態条件を満たしていない場合、特典が配布されず、「Transfer to Balance」の操作も利用できない場合があります。
  * 無効な招待コードでも登録は妨げられず、登録済みのユーザーが招待コードを再利用しても特典は再度受け取れません。
</Callout>

## 注文履歴

* チャージカードの右上の「Order History」をクリックすると、チャージおよび決済の注文記録を確認できます。
* ページでは注文番号で検索でき、ページネーションに対応しています。注文番号、作成時刻、支払い方法、チャージクォータまたは金額、支払金額、注文状態を表示します。

<Callout type="info">
  1. 一般ユーザーは過去 30 日間の自分の記録のみ検索できます。検索条件は注文番号のみに一致します。
  2. この一覧は主にチャージと決済の注文を表示するためのもので、すべてのサブスクリプション注文を網羅することを保証しません。
</Callout>

## よくある制限

以下の状況では、ウォレットやサブスクリプション関連機能が利用できなくなることがあります：

1. プラットフォームに決済ゲートウェイや決済製品が未設定のため、利用可能な支払い方法やサブスクリプションプランがありません。
2. 決済コンプライアンスの状態条件を満たしていないため、支払い方法やサブスクリプションプランが利用できず、引き換えコードの操作が無効な状態で表示されます。
3. チャージ金額が、プラットフォームまたはゲートウェイが要求する最低金額を下回っています。
4. 残高が不足している、プランが無効化されている、または個人の購入上限に達しています。
5. サードパーティの決済コールバックがまだ完了せず、注文が処理中です。

<Callout type="warn">
  支払いは成功しているのに、注文や残高が長時間更新されない場合は、注文番号、支払い証明、発生時刻を控え、プラットフォーム管理者に確認してください。二重支払いはしないでください。
</Callout>
