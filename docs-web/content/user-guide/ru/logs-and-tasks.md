# Журналы и асинхронные задачи

* Uter хранит сведения о запросах, записи о генерации и асинхронные задачи, такие как видео и музыка, отдельно друг от друга.
* После входа доступны «Журналы использования» или «Журналы задач» на левой панели навигации.
* Эта страница единообразно объясняет три раздела данных, статусы задач и методы запроса через API.

Три раздела соответствуют следующим путям:

* `/usage-logs/common`: общие журналы использования API и сведения о биллинге;
* `/usage-logs/drawing`: задачи генерации изображений Midjourney;
* `/usage-logs/task`: общие асинхронные задачи, например Suno и видео.

<Callout type="info">
  Обычные пользователи могут просматривать только собственные записи. Admin и Root могут переключаться между «Все» и «Только мои» в правом верхнем углу страницы; при переключении на «Только мои» страница возвращает данные в соответствии с полями и правами обычного пользователя.
</Callout>

## Журналы использования

* «Журналы использования» доступны в левой боковой панели; также можно перейти на `/usage-logs/common`, чтобы просмотреть запросы API и сведения о биллинге.

### Фильтрация записей

Доступные параметры фильтрации для запроса записей журнала использования:

| Параметр фильтрации | Описание |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| Временной диапазон | Фильтрация по времени создания записи, при этом в диапазон запроса включаются как начальное, так и конечное время. |
| Название модели | Фильтрация по названию модели. |
| Группа | Фильтрация по группе, использованной в запросе. |
| Тип журнала | Все типы, Пополнение, Потребление, Управление, Система, Ошибка, Возврат, Вход. |
| Название ключа API | Фильтрация по названию ключа API. |
| Идентификатор запроса | Поиск запроса по идентификатору запроса Uter. |
| Идентификатор запроса апстрима | Поиск запроса по идентификатору, возвращаемому или фиксируемому апстрим-сервисом. |
| Имя пользователя (только Admin/Root) | Фильтрация по имени пользователя в представлении администратора. |
| Идентификатор канала (только Admin/Root) | Фильтрация по идентификатору канала в представлении администратора. |

### Статистика страницы

Статистические значения на панели фильтрации зависят от текущих прав и условий фильтрации:

* **Расход**: агрегирует квоту по записям потребления, которую можно фильтровать по времени, модели, группе, ключу, каналу и пользователю.
* **RPM**: количество запросов потребления за последние 60 секунд.
* **TPM**: суммарное количество входных и выходных Токенов за последние 60 секунд.

### Список и подробности

* Обычные пользователи видят столбцы «Время и тип», «Токен», «Модель», «Поток», «Токены», «Стоимость», «Длительность» и «Подробности».
* В представлении Admin/Root дополнительно отображаются столбцы «Канал» и «Пользователь».

<img alt="Страница журналов использования" src="01-usage-logs.webp" />

<Callout type="info">
  1. **Токены**: отображает входные и выходные Токены; при использовании кэша могут также отображаться объёмы чтения и записи кэша.
  2. **Стоимость**: отображает списание квоты или результат возврата по этой записи; конкретный формат зависит от способа отображения квоты в экземпляре.
  3. **Длительность**: отображает длительность ответа для записей потребления или ошибок с данными о времени; для потоковых запросов дополнительно могут отображаться время первого ответа (FRT) и сведения о пропускной способности.
  4. **Подробности**: нажатие на запись открывает диалоговое окно с подробностями. В зависимости от типа журнала и фактически сохранённых в записи полей он может содержать идентификатор запроса, сопоставление моделей, причину ошибки или возврата, сведения о Токенах, детали биллинга, использование кэша, аудио и изображений, статус потока и т. д. Не каждый блок отображается в каждой записи.
  5. Администраторы могут также видеть в подробностях цепочки повторов по каналам, преобразования запросов, пути биллинга, аудит пополнений или аудит административных операций.
</Callout>

<Callout type="warn">
  * **Почему не видно конкретную запись?**
    Запись журналов потребления определяется переключателем «Записывать расход квоты» в разделе «Системные настройки» → «Эксплуатация» → «Обслуживание журналов». Если Root отключит эту настройку, новые записи потребления могут не создаваться. Журналы ошибок также зависят от переключателя журнала ошибок и типов ошибок, подлежащих записи; не каждый неудачный ответ формирует запись «Ошибка». Параметр «Записывать IP-адреса» в профиле пользователя управляет только тем, сохраняются ли IP-адреса запросов в журналах потребления и журналах ошибочных запросов; другие журналы, например вход, административный аудит и пополнение, могут фиксировать IP-адреса в соответствии с собственными процедурами аудита.
</Callout>

## Журналы задач

* «Журналы задач» включают «Журналы генерации» и «Журналы асинхронных задач».

1. «Журналы генерации»: фиксируют журналы задач генерации изображений Midjourney.
2. «Журналы асинхронных задач»: фиксируют асинхронные задачи, например преобразование текста в видео, преобразование изображения в видео и генерацию аудио.

## Журналы генерации

* «Журналы задач» → «Журналы генерации» доступны в левой боковой панели; также можно перейти на `/usage-logs/drawing`, чтобы просмотреть записи о задачах генерации изображений Midjourney.
* Обычные пользователи могут просматривать только собственные задачи; Admin/Root могут видеть задачи в пределах своего зоны ответственности в представлении «Все», а также дополнительно видеть каналы и результаты отправки.

Журналы генерации поддерживают фильтрацию по следующим условиям:

1. Диапазон дат;
2. Идентификатор задачи Midjourney;
3. Идентификатор канала (только Admin/Root).

<img alt="Страница журналов генерации" src="02-drawing-logs.webp" />

<Callout type="info">
  1. Список включает время и статус отправки, идентификатор канала (только Admin/Root), тип операции, идентификатор задачи, длительность, результат отправки, ход выполнения, изображение, промпт и причину ошибки. Нажатие на изображение открывает предпросмотр; нажатие на промпт показывает полное содержимое; нажатие на причину ошибки показывает полное сообщение об ошибке.
  2. Статусы генерации включают: «Не начато», «В очереди», «В процессе», «Успешно», «Ошибка», «Ожидание окна».
  3. Статусы генерации обновляются путём фонового опроса апстрим-задач. Поскольку существует интервал опроса, статус задачи может отображаться с задержкой; когда серверная часть получает соответствующие данные апстрим-задачи, система помечает задачи Midjourney, отправленные более чем примерно час назад и всё ещё не завершённые, как ошибочные.
</Callout>

## Журналы задач (журналы асинхронных задач)

* «Журналы задач» → «Журналы асинхронных задач» доступны в левой боковой панели; также можно перейти на `/usage-logs/task`, чтобы просмотреть журналы асинхронных задач. Обычные пользователи могут просматривать только собственные задачи; в представлении Admin/Root дополнительно отображаются идентификатор канала и пользователь.
* Асинхронные API для видео, музыки и т. д. не возвращают окончательный результат сразу после отправки запроса. После успешной отправки Uter возвращает общедоступный идентификатор задачи и сохраняет запись о задаче, после чего серверная часть опрашивает апстрим-сервис для обновления статуса, хода выполнения и результатов.

### Фильтрация задач

Журналы задач поддерживают фильтрацию по следующим условиям:

1. Диапазон дат;
2. Идентификатор задачи;
3. Идентификатор канала (только Admin/Root).

### Список и результаты

Список задач отображает время отправки и завершения, канал, пользователя, идентификатор задачи, платформу и операцию, длительность, статус, ход выполнения и подробности:

* при успешном выполнении задачи Suno и возврате адреса аудио столбец подробностей предоставляет предпросмотр аудио;
* некоторые видеозадачи отображают запись для предпросмотра после успешного завершения; также можно использовать сеанс входа или ключ API той же учётной записи для запроса `/v1/videos/{task_id}/content`, чтобы получить видеосодержимое завершённых задач. Этот API проверяет принадлежность задачи; содержимое не возвращается, если задача не завершена или не принадлежит текущему пользователю;
* у других ошибочных записей причина ошибки отображается в столбце подробностей, по ней можно щёлкнуть, чтобы просмотреть полную информацию.

## Статус задачи и обработка на серверной стороне

Для журналов асинхронных задач используются следующие значения статуса. Разные адаптеры платформ иногда сохраняют регистр или особенности апстрим-статусов, поэтому возвращаемые значения API следует основывать на фактических записях задач:

| Статус | Значение |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `Not Started` | Запись о задаче создана, но ещё не начала обрабатываться. |
| `Queued` | Отправлено в апстрим, ожидает дальнейшей обработки. |
| `In Queue` | Помещено в очередь обработки. |
| `In Progress` | Выполняется обработка. |
| `Success` | Завершено, результаты можно просмотреть или получить. |
| `Failed` | Обработка не удалась; причина сбоя будет записана в запись задачи (если её предоставил апстрим). |
| `Unknown` | Внутреннее запасное значение для неизвестного статуса. |

<img alt="Страница журналов задач" src="03-task-logs.webp" />

<Callout type="info">
  Статусы задач обновляются путём фонового опроса, поэтому статус только что отправленных задач может отображаться с задержкой. По умолчанию асинхронные задачи опрашиваются примерно каждые 15 секунд; опрос выполняется только при включённом `UPDATE_TASK` и наличии незавершённых задач. Порог тайм-аута асинхронных задач задаётся параметром `TASK_TIMEOUT_MINUTES`, значение по умолчанию — 1440 минут; установка значения `0` отключает обработку тайм-аутов.
</Callout>

### Сбой, тайм-аут и возврат средств

После перехода задачи в состояние конечного сбоя, если на этапе отправки по задаче была предварительно списана квота, система обычно пытается выполнить возврат средств и записать журнал `Refund` при успешном возврате. После успешного возврата ожидающий возврата квоты в записи задачи очищается, а накопленный расход для пользователя и канала уменьшается; при этом количество запросов не откатывается.

<Callout type="warn">
  Следующие ситуации могут привести к временным расхождениям между статусом на странице и балансом:

  1. По задаче не было предварительно списано квоту (`quota = 0`);
  2. Возврат средств из источника пополнения не удался, поэтому система сохраняет квоту задачи для повторной попытки или ручной сверки;

  * При диагностике возвратов следует проверять как баланс кошелька или остаток квоты подписки (а также квоту активных ключей API), так и записи «Возврат» в общих журналах использования. Нельзя полагаться только на статус «Ошибка» для определения того, завершён ли возврат средств.
</Callout>

## Справочник API

### API запроса журналов

При использовании API вместо консоли доступны следующие API только для чтения. Эти API также подчиняются ограничениям аутентификации и прав доступа, а результаты для обычных пользователей строго ограничиваются текущей учётной записью:

| Данные | API администратора | API пользователя | Единица параметра времени |
| ------------------ | ------------------- | ------------------------ | ---------------------------- |
| Общие журналы | `GET /api/log/` | `GET /api/log/self` | Секунды (`created_at`) |
| Статистика журналов | `GET /api/log/stat` | `GET /api/log/self/stat` | Секунды |
| Генерация Midjourney | `GET /api/mj/` | `GET /api/mj/self` | Миллисекунды (`submit_time`) |
| Асинхронные задачи | `GET /api/task/` | `GET /api/task/self` | Секунды (`submit_time`) |

Для списков журналов и задач используются параметры разбиения на страницы `p` и `page_size`; нумерация страниц начинается с `1`. При использовании обычных положительных целых чисел значение `page_size`, превышающее `100`, обрезается до `100`. На суммарное количество журналов пользователя также влияет внутренний лимит запросов экземпляра. Возвращаемые данные задач не включают приватные поля, которые могут содержать ключи, идентификаторы апстрим-задач или контекст биллинга.

Кроме того, `GET /api/log/token` можно использовать с ключом API для чтения последних журналов по этому ключу. Этот API использует аутентификацию токеном только для чтения: он проверяет, что ключ существует, не отключён явно и что его владелец-пользователь доступен, но не отклоняет запросы из-за истечения срока действия ключа или исчерпания квоты; возвращается не более `1000` последних записей.

Общие параметры запроса для API списка задач:

| Область | Метод и путь | Общие параметры запроса |
| ------------ | -------------------- | ------------------------------------------------------------------------------------------------------------- |
| Текущий пользователь | `GET /api/task/self` | `p`, `page_size`, `task_id`, `start_timestamp`, `end_timestamp`; также принимает `platform`, `action`, `status`. |
| Admin/Root | `GET /api/task/` | Добавляет `channel_id` к параметрам API пользователя и позволяет фильтровать по `platform`, `action`, `status`. |

<Callout type="info">
  Значения `start_timestamp` и `end_timestamp` для API задач используют временные метки Unix в секундах; параметры времени API генерации Midjourney используют миллисекунды.
</Callout>

### Асинхронная генерация и API задач

Экземпляр предоставляет следующие API асинхронной генерации и запроса апстрим-задач в соответствии с настроенными каналами и адаптерами. API отправки и запроса, как правило, используют аутентификацию по ключу API. Прокси видеосодержимого поддерживает как ключи API, так и сеансы входа и проверяет принадлежность задачи; прокси изображений Midjourney является исключением и не требует ключа API; приведённый ниже API списка `/api/task` использует права авторизованного пользователя или администратора. Конкретный способ аутентификации определяется требованиями API.

| API | Путь | Описание |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Генерация видео OpenAI | `POST /v1/videos` | Создаёт совместимую с OpenAI асинхронную задачу генерации видео и при успехе возвращает идентификатор задачи. |
| Запрос задачи видео OpenAI | `GET /v1/videos/{task_id}` | Запрашивает статус, ход выполнения и сведения о результате задачи генерации видео. |
| Получение видеосодержимого | `GET /v1/videos/{task_id}/content` | Возвращает потоком завершённое видеосодержимое; система получает содержимое из апстрима по результатам задачи или декодирует сохранённые URL данных. |
| Ремикс видео | `POST /v1/videos/{video_id}/remix` | Отправляет новую асинхронную задачу ремикса на основе существующего видео. |
| Устаревшая генерация видео | `POST /v1/video/generations` | Совместима с устаревшими путями генерации видео, создаёт асинхронные видеозадачи. |
| Запрос устаревшей видеозадачи | `GET /v1/video/generations/{task_id}` | Запрашивает статус и результаты устаревших задач генерации видео. |
| Преобразование текста в видео Kling | `POST /kling/v1/videos/text2video` | Отправляет задачу преобразования текста в видео в формате Kling; сначала система выполняет преобразование формата запроса. |
| Преобразование изображения в видео Kling | `POST /kling/v1/videos/image2video` | Отправляет задачу преобразования изображения в видео в формате Kling. |
| Запрос задачи Kling | `GET /kling/v1/videos/text2video/{task_id}` `GET /kling/v1/videos/image2video/{task_id}` | Запрашивает результаты задач преобразования текста или изображения в видео Kling. |
| Официальный API Jimeng | `POST /jimeng/` | Совместим с официальным форматом API Jimeng, различая отправку задач и запросы через такие параметры, как `Action` и `Version`. |
| Отправка задачи Suno | `POST /suno/submit/{action}` | Отправляет задачу генерации музыки Suno; конкретный тип задачи определяется параметром `action`. |
| Запрос задачи Suno | `POST /suno/fetch` `GET /suno/fetch/{id}` | Запрашивает список задач Suno либо статус и результаты указанной задачи. |
| Отправка задачи Midjourney | `POST /mj/submit/{action}` `POST /{mode}/mj/submit/{action}` | Поддерживает операции с задачами, такие как `imagine`, `describe`, `blend`, `change`, `simple-change`, `edits`, `video`, `action`, `modal` и `shorten`. |
| Запрос задачи Midjourney | `GET /mj/task/{id}/fetch` `GET /mj/task/{id}/image-seed` `POST /mj/task/list-by-condition` | Запрашивает статус задачи, начальные значения изображений или списки задач по условиям; также поддерживает пути с префиксом `{mode}`. |
| Прокси изображений Midjourney | `GET /mj/image/{id}` `GET /{mode}/mj/image/{id}` | Получает или проксирует сгенерированные изображения по идентификатору задачи Midjourney. |
| Расширенные операции Midjourney | `POST /mj/insight-face/swap` `POST /mj/submit/upload-discord-images` | Предоставляет расширенные возможности, такие как замена лиц и загрузка изображений Discord. |

## Взаимосвязь с панелью данных

* Журналы содержат подробные записи, тогда как панель данных предоставляет статистику, агрегированную по времени, модели, пользователю или каналу.
* Их области фильтрации, периоды обновления и методы статистики могут различаться;
* Новые запросы сначала появляются в журналах, а данные на графиках могут потребовать агрегации или обновления перед отображением.

<Callout type="info">
  При диагностике вызова рекомендуется сначала найти запрос в общих журналах по времени, модели, идентификатору запроса или идентификатору запроса апстрима; для асинхронных запросов следует записать `task_id`, возвращённый API отправки, а затем запросить итоговый статус задачи и сведения о сбое. Если задача долго не изменяется, необходимо проверить доступность канала, переключатель опроса задач, настройки тайм-аутов и соответствующие записи «Возврат».
</Callout>
